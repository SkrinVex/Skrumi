## 1. Быстрый старт

```cpp
// hello.skm
void main() {
    string name = "мир";
    print("Привет, " + name + "! 🦊");
}

main();
```

```bash
skrumi hello.skm            # запустить
skrumi check hello.skm      # проверить без запуска
skrumi build hello.skm      # собрать самостоятельный исполняемый файл
```

Программа выполняется сверху вниз. Функция `main` не обязательна: это обычная
функция, которую в примере вызывает последняя строка.

## 2. Синтаксис

* Каждая инструкция заканчивается точкой с запятой `;`, блоки заключаются в `{ ... }`.
* Комментарий начинается с `//` и идёт до конца строки. Блочных комментариев нет.
* Идентификаторы состоят из латинских букв, цифр и `_` и не начинаются с цифры:
  `user_name`, `score2`. Кириллица допустима в строках и комментариях, но не в именах.
* Тело `if`, `while`, `for` и функции всегда пишется в фигурных скобках.
* Числа: целые `42` и дробные `3.14` (цифра обязательна по обе стороны точки).
  Шестнадцатеричной и экспоненциальной записи нет.
* Строки пишутся в двойных кавычках. Соседние строковые литералы склеиваются,
  поэтому длинный текст можно разбить на несколько строк исходника.
* Внутри строки `${выражение}` подставляет значение выражения так, как его показывает
  `print`: `"Привет, ${name}! Тебе ${age + 1}"`. Внутри `${ }` можно писать любое
  выражение, в том числе со строками и фигурными скобками. `\$` — просто знак доллара,
  одиночный `$` без `{` тоже остаётся текстом.

Escape-последовательности в строках:

| Запись | Значение |
|---|---|
| `\n`, `\t`, `\r` | перевод строки, табуляция, возврат каретки |
| `\"`, `\\` | кавычка и обратная косая черта |
| `\0` | нулевой символ |
| `\$` | знак доллара, который не начинает `${` |
| `Л` | символ Unicode по четырём шестнадцатеричным цифрам |
| `\u{1F98A}` | символ Unicode по 1–6 цифрам, например emoji |
| `🦊` | суррогатная пара UTF-16, как в JSON, — один символ 🦊 |

Любой другой символ после `\` означает сам себя.

```cpp
string fox = "\u{1F98A}";
string same = "🦊";
string text = "Первая строка\n"
              "вторая строка";
print(fox == same, text);

string name = "Лис";
int age = 3;
print("Привет, ${name}! Через год тебе будет ${age + 1}.");
```

Ключевые слова: `if`, `else`, `while`, `for`, `switch`, `case`, `default`,
`break`, `continue`, `return`, `try`, `catch`, `finally`, `throw`, `struct`, `global`,
`using`, `include`, типы `int`, `float`, `string`, `bool`, `void`, `array`, `map` и
литералы `true`, `false`. Встроенные функции
(`print`, `size`, `read_file` и остальные) — обычные имена, а не ключевые слова.

## 3. Типы и преобразования

| Тип | Значения |
|---|---|
| `int` | целое от `-2147483648` до `2147483647` |
| `float` | число с плавающей точкой двойной точности (IEEE 754) |
| `string` | текст UTF-8 |
| `bool` | `true` или `false` |
| `array` | массив значений любых типов, см. [раздел 8](#8-массивы) |
| `map` | словарь «ключ → значение», см. [раздел 9](#9-словари-map) |
| имя структуры | значение структуры, объявленной `struct`, см. [раздел 10](#10-структуры-struct) |
| имя перечисления | одно из значений, объявленных `enum`, см. [перечисления](#перечисления-enum) |
| `func` | функция как значение: лямбда, функция Skrumi или встроенная, см. [раздел 7](#функции-как-значения-и-лямбды) |
| `T?` | значение типа `T` или `null`, см. [ниже](#null-и-типы-t) |
| `void` | «нет значения»: только тип результата функции |

`int` не переполняется молча: значение вне диапазона — в объявлении, при
присваивании или в результате арифметики — это ошибка выполнения. `float` хранит
значение в двоичном формате IEEE 754 binary64 и печатается кратчайшей записью, которая читается обратно в то
же число, поэтому `0.1 + 0.2` печатается как `0.30000000000000004` — это свойство
двоичной плавающей точки.

**Правило преобразования.** Когда значение попадает в место с объявленным
типом — переменную, параметр функции или результат функции, — работает одно и то
же правило:

| Место | Принимает |
|---|---|
| `int` | только `int`; для `float` требуется явное `to_int(value)` |
| `float` | `float` и `int` |
| `string` | `string`; `int`, `float` и `bool` превращаются в свой текст |
| `bool` | только `bool` |
| `array` | только `array` |
| `map` | только `map` |
| `func` | только функция |
| структура `Point` | только значение `Point` |

Всё остальное — ошибка `Type Error`. Строку в число явно превращают `to_int` и
`to_float`, число в строку — `to_string` или сложение со строкой.

```cpp
int whole = to_int(9.99);          // 9
float wide = 10;           // 10
string label = 42;         // "42"
string state = true;       // "true"
int port = to_int("8080");
float ratio = to_float("0.75");
print(whole, wide, label, state, port, ratio, type_of(ratio));
```

Неявное `float → int` запрещено также для параметров, возвращаемых значений,
полей структур, элементов типизированных контейнеров и параметров builtin с типом
`int`. Даже `2.0` требует `to_int(2.0)`. `to_int` отбрасывает дробную часть к нулю
и проверяет диапазон. Расширение `int → float` остаётся неявным.

### null и типы T?

`null` — «значения нет». Обычная переменная его не хранит: `string name = null;` —
ошибка. Тип со знаком вопроса, `T?`, принимает и значения `T`, и `null`; так
объявляют переменные, параметры, поля структур и результаты функций, у которых
значения может не быть.

```cpp
string? nick = null;            // или просто `string? nick;`
print(nick ?? "аноним");        // аноним
nick = "лис";
print(nick ?? "аноним");        // лис

string? find_user(array names, string prefix) {
    for (name in names) {
        if (str_starts_with(name, prefix)) {
            return name;
        }
    }
    return null;
}
print(find_user(["ann", "bob"], "b"), find_user(["ann"], "z") == null);

struct Employee {
    string name;
    Employee? boss;             // по умолчанию null
}
Employee ann = Employee("Ann");
Employee bob = Employee("Bob", ann);
print(bob.boss?.name, ann.boss?.name, ann.boss?.name ?? "нет");
```

* `a ?? b` — `a`, если оно не `null`, иначе `b`; `b` вычисляется только тогда.
  Цепочка `a ?? b ?? c` даёт первое не-`null` значение.
* `a?.поле` и `a?.метод(...)` дают `null`, если `a` — `null`, вместо ошибки;
  аргументы метода тогда не вычисляются.
* `x == null` и `x != null` проверяют наличие значения; `null` равен только `null`.
  Остальные операторы с `null` — ошибка, как и условие `if (x)`, когда `x` — `null`.
* Переменная `T?` без начального значения равна `null`, поле `T?` — тоже. Значение
  в неё попадает по [правилу преобразования](#3-типы-и-преобразования) для `T`:
  `float? ratio = 1;` хранит `1.0`.
* Функция с результатом `T?` может вернуть `null` явно (`return null;`) или выйти без
  `return` — результат тоже `null`.
* `print(null)` и `"${null}"` показывают `null`, `type_of(null)` — `"null"`.
  `json_decode` превращает JSON `null` в `null`, `json_value` — обратно.
* `func?` — функция, которой может не быть: поле `func? on_click;` не обязательно
  задавать при создании структуры.
* `skrumi check` сообщает, когда `null` попадает в переменную, параметр или
  результат функции без `?`.

## 4. Переменные и области видимости

Переменная объявляется с типом и обязательным начальным значением:

```cpp
int health = 100;
float gravity = 9.8;
string player_name = "Лис";
bool is_alive = true;
health = health - 10;
```

Объявление без значения (`int x;`) не допускается; пустой массив объявляется как
`array items;`, а переменная типа `T?` без значения равна `null`.

**Константы.** `const` перед объявлением запрещает присваивать имени новое
значение: `=`, `+=` и `++` для константы — ошибка, и `skrumi check` сообщает о ней
заранее. Константа объявляется только со значением.

```cpp
const int MAX_PLAYERS = 4;
const string TITLE = "Лисья нора";
const array LEVELS = ["лес", "поле"];
push(LEVELS, "гора");     // можно: меняется содержимое, а не имя
print(TITLE, MAX_PLAYERS, LEVELS);
```

Как и `final` в Java или `const` в JavaScript, константа защищает имя, а не
содержимое: элементы массива, ключи словаря и поля структуры по-прежнему можно
менять.

**Области видимости.** Каждый блок `{ ... }` — отдельная область: тело функции,
ветка `if`, тело цикла. Переменная видна от объявления до конца своего блока. Тело
цикла — новая область на каждом витке, поэтому объявление внутри цикла не
конфликтует само с собой. Счётчик `for (int i = 0; ...)` принадлежит циклу.

Во вложенной области имя можно объявить заново — оно затеняет внешнее до конца
блока. Повторное объявление в **той же** области — ошибка.

```cpp
int total = 10;
{
    int local = 5;
    int total = 1;        // затеняет внешнюю total внутри блока
    print(local + total); // 6
}
print(total);             // 10
```

**Функции и глобальные переменные.** Функция видит свои параметры, свои локальные
переменные и переменные верхнего уровня программы. Локальные переменные вызывающей
функции ей недоступны.

`global` внутри функции объявляет переменную (или массив) на верхнем уровне
программы, как если бы объявление стояло там:

```cpp
void setup() {
    global int score = 0;
    global array history;
}

setup();
score += 5;
push(history, score);
print(score, history);
```

## 5. Операторы

| Приоритет | Операторы | Описание |
|---|---|---|
| 1 (высший) | `-x`, `!x`, `x++`, `x--`, `a[i]`, `a.b`, `a?.b`, вызов `f()` | унарные, постфиксные, индекс, поле |
| 2 | `*`, `/`, `%` | умножение, деление, остаток |
| 3 | `+`, `-` | сложение и склейка строк, вычитание |
| 4 | `==`, `!=`, `<`, `>`, `<=`, `>=` | сравнение |
| 5 | `&&` | логическое И |
| 6 | `\|\|` | логическое ИЛИ |
| 7 (низший) | `??` | значение по умолчанию вместо `null`, см. [null](#null-и-типы-t) |

Присваивания — отдельные инструкции: `=`, `+=`, `-=`, `*=`, `/=`, `%=`. Они же
работают для элементов массива: `items[i] += 1;`.

* **Арифметика.** Если хотя бы один операнд `float`, результат `float`, иначе `int`.
  Деление двух `int` целочисленное с отбрасыванием дробной части: `7 / 2` даёт `3`,
  `-7 / 2` даёт `-3`. Знак остатка совпадает со знаком делимого. Деление на ноль —
  ошибка выполнения.
* **`+` со строкой** превращает второй операнд в текст: `"n=" + 5 + ", ok=" + true`.
* **Сравнение** строк идёт по байтам UTF-8, чисел — по значению (`1 == 1.0`),
  `bool` — между собой. Строка, сравниваемая с числом, должна содержать число.
  Массивы поддерживают `==` и `!=`: это рекурсивное сравнение содержимого, а не ссылок.
* **Логические операторы** принимают только `bool` и вычисляют правую часть лишь
  при необходимости, поэтому такая проверка безопасна:

```cpp
int divisor = 0;
int total = 10;
if (divisor != 0 && total / divisor > 1) {
    print("ok");
}
```

* **`i++` и `i--`** увеличивают или уменьшают переменную `int` или `float` на 1 и
  возвращают старое значение.

## 6. Управляющие конструкции

Условие `if`, `while` и `for` обязано иметь тип `bool`: число вместо условия —
ошибка типа, а не «ложь».

```cpp
int x = 10;
if (x > 10) {
    print("больше");
} else if (x == 10) {
    print("ровно десять");
} else {
    print("меньше");
}

int i = 0;
while (i < 3) {
    i++;
}

for (int k = 0; k < 10; k++) {
    if (k == 2) {
        continue;
    }
    if (k == 5) {
        break;
    }
    print(k);
}

for (;;) {
    break; // все три части for необязательны
}
```

**Цикл по элементам.** `for (x in значение)` проходит по массиву, словарю или строке;
с двумя переменными `for (a, b in значение)` получает ещё и номер или ключ:

| Что перебирается | `for (x in …)` | `for (a, b in …)` |
|---|---|---|
| массив | элементы | номер элемента и элемент |
| словарь | ключи в порядке добавления | ключ и значение |
| строка | символы (не байты) | номер символа и символ |

Перед именем переменной можно указать тип, тогда значение к нему приводится:
`for (string name, int age in ages)`. Без типа переменная принимает то, что даёт цикл.
Переменные цикла видны только внутри него; `break` и `continue` работают как обычно.
Если массив меняется во время обхода, цикл видит изменения: он берёт элемент по
номеру на каждом шаге.

```cpp
array scores = [5, 3, 4];
int sum = 0;
for (s in scores) {
    sum += s;
}
map ages = {"Анна": 30, "Борис": 25};
for (string name, int age in ages) {
    print("${name}: ${age}");
}
for (i, ch in "Лис") {
    print(i, ch);   // 0 Л, 1 и, 2 с
}
```

`switch` сравнивает значение с каждым `case`: числа по величине, строки по тексту.
Без `break` выполнение переходит в следующую ветку, включая `default`, который
должен идти последним. `continue` внутри `switch` продолжает окружающий цикл.

```cpp
string day = "сб";
switch (day) {
    case "сб":
    case "вс":
        print("выходной");
        break;
    default:
        print("рабочий день");
}
```

## 7. Функции

```cpp
int add(int a, int b) {
    return a + b;
}

void greet(string name) {
    print("Привет, " + name + "!");
}

int factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}

greet("Алиса");
print(add(2, 3), factorial(5));
```

* Тип результата — `int`, `float`, `string`, `bool`, `array`, `map`, `func`, имя
  структуры или `void`. Параметры имеют те же типы, кроме `void`. Параметр можно
  объявить без типа — тогда он принимает значение любого типа как есть:
  `void log_all(label, value)`.
* Аргументы и возвращаемое значение приводятся к объявленным типам по
  [правилу преобразования](#3-типы-и-преобразования): `float half(int v)` вернёт
  `float`, даже если `return` получил `int`.
* Функция с типом результата, отличным от `void`, обязана вернуть значение: выход из
  неё без `return` — ошибка выполнения. `void`-функция не может вернуть значение.
* Количество аргументов должно совпадать с числом параметров.
* Функции и структуры верхнего уровня файла существуют с самого начала его выполнения,
  поэтому функцию можно вызвать выше строки, где она объявлена. Если функция с таким
  именем уже есть (например, из подключённого модуля), до строки нового объявления
  действует прежняя.
* Бесконечная рекурсия завершается ошибкой `call depth limit` с числом вызовов, а не
  аварийным падением. Функции вызывают друг друга до 100 000 уровней в глубину:
  виртуальная машина ведёт их стек сама, в обычной памяти. Лямбды, методы и функции,
  которые вызывает встроенная (например, `array_sort` своё сравнение), идут через
  стек потока: при обычных 8 МБ это несколько тысяч уровней.
* `return` вне функции — ошибка.

**Функции и встроенные функции с одинаковым именем.** Объявленная функция Skrumi
затеняет встроенную по имени, независимо от количества и типов аргументов.
Неподходящие аргументы дают ошибку выбранной функции; перехода к другой функции нет.
Это же правило действует для `func f = имя;`. Переменная типа `func` имеет
приоритет перед именем функции.

Для явного выбора модуля используйте `using server as http;` и
`http.get("/users", handler)`. Импорт по-прежнему добавляет функции в общее
пространство имён, поэтому после импорта `server` обычный `get(...)` означает
его функцию регистрации маршрута. Элемент массива можно читать через `items[index]`.
Псевдоним фиксирует модульную функцию, даже если позже объявлена одноимённая функция.

`check` и LSP проверяют доступные статические сведения, включая число аргументов
выбранной функции и известное сужение `float → int`. Нетипизированные параметры и
динамические значения остаются предметом проверки runtime; успешный `check` не
гарантирует отсутствия ошибок выполнения.

### Функции как значения и лямбды

Функцию можно положить в переменную типа `func`, передать аргументом и вернуть из
другой функции. Значением служит лямбда, имя функции Skrumi или имя встроенной
функции; переменную типа `func` вызывают как обычную функцию.

```cpp
func twice = (int x) => x * 2;          // тело-выражение
func greet = (string name) => {         // тело-блок
    print("Привет, " + name + "!");
};
func half = x => x / 2.0;               // один параметр без типа — без скобок

int add(int a, int b) { return a + b; }
func plus = add;                        // функция по имени
func say = print;                       // и встроенная тоже

int apply(func f, int value) { return f(value); }

greet("Лис");
print(twice(21), plus(2, 3), apply(x => x * x, 7), half(5));
say("функции", "как", "значения");
```

* Лямбда записывается как `(параметры) => выражение` или `(параметры) => { ... }`.
  У параметров тип можно не указывать: тогда они принимают значение любого типа.
  Параметры с типом приводятся по [правилу преобразования](#3-типы-и-преобразования).
* Лямбда с телом-выражением возвращает его значение. В теле-блоке `return` с
  значением или без него разрешён; без `return` результатом будет «нет значения».
* Количество аргументов должно совпадать с числом параметров, как и у функций.
* Вызов переменной, в которой не функция, — ошибка `Type Error: 'x' is not a function`.
* `print` показывает функцию как `<func имя>`, лямбду — как `<func lambda>`.
  `type_of` возвращает `"func"`. Две функции равны (`==`), если это одна и та же функция.

**Замыкания.** Лямбда видит локальные переменные функции, в которой создана, и
продолжает их видеть после выхода из неё. Переменная общая: изменение внутри лямбды
видно снаружи и наоборот.

```cpp
func make_counter() {
    int count = 0;
    return () => {
        count++;
        return count;
    };
}

func next = make_counter();
next();
next();
print(next()); // 3

func adder(int n) { return x => x + n; }
func add5 = adder(5);
print(add5(10)); // 15
```

* Каждая итерация цикла создаёт свои переменные: лямбды, созданные в
  `for (item in items)`, запоминают каждая свой `item`.
* Локальная переменная `func` видна в собственной лямбде, поэтому лямбда может
  вызывать себя рекурсивно:

```cpp
void show() {
    func fact = (int n) => {
        if (n <= 1) {
            return 1;
        }
        return n * fact(n - 1);
    };
    print(fact(5)); // 120
}
show();
```

* Глобальные переменные лямбда читает по имени в момент вызова, как и функции.

Функции высшего порядка для массивов — `array_map`, `array_filter`, `array_reduce`,
`array_find`, `array_any`, `array_all` и `array_sort` с функцией сравнения — описаны в
[разделе 12](#массивы), удобные обёртки — в [модуле arrays](#using-arrays).

## 8. Массивы

Массив хранит значения любых типов и может менять размер.

```cpp
array zeros; resize(zeros, 3);                 // три элемента, равные 0
array primes = [2, 3, 5, 7];   // литерал
array names;                   // пустой массив
push(names, "Лис");
push(names, "Волк");

primes[0] = 11;                // запись по индексу (с нуля)
primes[1] += 1;
print(primes[0], size(primes), names);   // 11 4 [Лис, Волк]
print(zeros);                  // [0, 0, 0]
```

* Начальный размер задают отдельным вызовом `resize(имя, размер)`; размер — `int`.
* Чтение и запись вне границ `0..size-1` — ошибка выполнения.
* `get(items, i)` и `set(items, i, value)` — то же, что `items[i]` и `items[i] = value;`.
* Размер меняют `push`, `pop`, `insert`, `remove_at` и `resize`; алгоритмы —
  модуль [`arrays`](#arrays).
* `print` и `to_string` выводят массив как `[1, 2, 3]`.
* Элементом может быть любое значение, в том числе другой массив, словарь или
  структура: `grid[1][0] = 5;`, `users[0].name`.
* `==` и `!=` сравнивают массивы по содержимому: `[1, [2]] == [1, [2]]` истинно.

Следующий пример выполняется тестом документации.

<!-- skrumi-run -->
```cpp
array left = [1, [2]];
array right = [1, [2]];
assert_equal(left == right, true);
assert_equal(left != right, false);
right[1][0] = 3;
assert_equal(left == right, false);
array alias = left;
alias[0] = 7;
assert_equal(left[0], 7);
```

**Ссылки и копии.** Массив — это контейнер, а переменная хранит ссылку на него,
как в Python, JavaScript и Java. Присваивание `b = a;`, объявление `array b = a;`,
передача в функцию и возврат из неё не копируют элементы: все имена смотрят на один
и тот же массив, и изменение через любое из них видно через остальные. Независимую
копию делает `copy(a)` — вместе со всем, что вложено внутрь.

```cpp
void reset_first(array items) {
    items[0] = 0;
}

array evens(int count) {
    array result;
    for (int i = 0; i < count; i++) {
        push(result, i * 2);
    }
    return result;
}

array values = evens(4);
reset_first(values);
array same = values;
same[1] = 100;              // values тоже изменился
array backup = copy(values);
backup[2] = -1;             // а values — нет
print(values, backup);      // [0, 100, 4, 6] [0, 100, -1, 6]
```

**Время жизни.** Массив живёт, пока на него есть ссылка: переменная, элемент
другого контейнера или параметр вызванной функции. Освобождать его вручную не нужно.
Контейнер может содержать сам себя (`push(a, a);`): печать покажет такое место как
`[...]`, а `==` и `copy` с ним справляются.

Кольцо контейнеров, которые ссылаются только друг на друга (массив внутри себя,
две структуры с полями друг на друга, лямбда в словаре, который она сама видит),
по счётчику ссылок не освобождается никогда. Такие кольца находит **сборщик
циклов**: он запускается сам, когда с прошлого раза создано достаточно
контейнеров, и освобождает кольца, до которых программа уже не может добраться.
Долго работающий сервер поэтому не копит память. `gc_collect()` запускает его
сразу и возвращает число освобождённых контейнеров.

### Типизированные массивы и словари

`array<T>` — массив, все элементы которого имеют тип `T`; `map<string, T>` —
словарь с такими значениями (ключи словаря всегда текст). `T` — любой тип:
`int`, `string`, структура, перечисление, `T?` или снова контейнер.

```cpp
array<int> scores = [90, to_int(72.5), 88];     // 72.5 становится 72
push(scores, 100);
scores[0] = 95;

map<string, float> prices = {"чай": 3, "пирог": 4.5};
prices["кофе"] = 5;

array<array<string>> table = [["a", "b"], ["c"]];
push(table[1], "d");

int total(array<int> items) {
    int sum = 0;
    for (item in items) {
        sum += item;
    }
    return sum;
}
print(scores, total(scores), prices, table);
```

* Значение приводится к типу элемента по [правилу преобразования](#3-типы-и-преобразования)
  при объявлении и при каждой записи: `items[i] = ...`, `m[key] = ...`, `m.key = ...`,
  `push`, `insert`, `set`. Неподходящее значение — ошибка `Type Error`.
* Тип получает сам массив: после `array<int> scores = data;` массив `data` тоже
  проверяет элементы. Массив, уже типизированный по-другому, в `array<float>`
  не попадёт — это ошибка, а не незаметное преобразование.
* `array<int> empty;` — пустой массив, `array<int> zeros; resize(zeros, 5);` — пять нулей, `resize`
  добавляет пустые значения типа элемента (для структур — каждое своё).
* Обычные `array` и `map` по-прежнему принимают любые значения; `type_of` для
  типизированного массива — тоже `"array"`.
* `skrumi check` проверяет имя типа элемента и ключ `map<string, T>`.

## 9. Словари: map

Словарь хранит пары «ключ → значение». Ключ — строка (число `7` становится ключом
`"7"`), значение — что угодно, в том числе массив, другой словарь или структура.
Ключи помнят порядок, в котором их добавили.

```cpp
map ages = {"Ann": 30, Bob: 25};   // слово перед ':' — тоже текстовый ключ
ages["Cid"] = 41;                   // новый ключ
ages.Ann += 1;                      // .имя — то же, что ["имя"]
print(ages, size(ages));            // {Ann: 31, Bob: 25, Cid: 41} 3

if (has(ages, "Bob")) {
    remove_key(ages, "Bob");
}
int dan = get_or(ages, "Dan", 0);   // значения нет — берётся запасное
array names = keys(ages);           // [Ann, Cid]
for (int i = 0; i < size(names); i++) {
    print(names[i], ages[names[i]]);
}

map empty;                          // пустой словарь
map config = {"server": {"port": 8080, "hosts": ["a", "b"]}};
print(config.server.port, config["server"]["hosts"][1]);   // 8080 b
```

* Чтение отсутствующего ключа — ошибка выполнения с его именем; проверять ключ
  удобно через `has`, читать с запасным значением — через `get_or`.
* Запись по новому ключу добавляет его, `remove_key` удаляет.
* Ссылки — как у массивов: `map b = a;` и передача в функцию дают тот же словарь,
  `copy(a)` — независимую копию, `==` сравнивает содержимое.
* `json_decode` превращает JSON-объект в словарь, `json_value` — словарь в JSON.

## 10. Структуры: struct

Структура — составной тип с именованными полями фиксированных типов и
[методами](#методы). Объявляется на верхнем уровне файла; у поля может быть значение
по умолчанию.

```cpp
struct Point {
    int x;
    int y = 0;
}

struct User {
    string name;
    int age;
    array tags;
    Point home;
}

Point a = Point(3, 4);          // значения полей по порядку
Point b = Point(7);             // пропущенные в конце поля — по умолчанию: y = 0
Point origin;                   // все поля по умолчанию: 0, "", false, пустые контейнеры

User ann = User("Ann", 30, ["admin"]);
ann.age += 1;
ann.home.x = 10;
push(ann.tags, "dev");
print(ann);                     // User{name: Ann, age: 31, tags: [admin, dev], home: Point{x: 10, y: 0}}

float length(Point p) {
    return sqrt(p.x * p.x + p.y * p.y);
}

User older(User who) {
    who.age += 1;               // меняет переданную структуру
    return who;                 // и возвращает её же
}
print(length(a), older(ann).age, type_of(a));   // 5 32 Point
```

* Имя структуры — тип: `Point p`, параметр `User who`, результат `User older(...)`,
  элемент массива, значение словаря.
* Поле хранит объявленный тип: `ann.age = "старый";` — ошибка `Type Error`, `int`
  в поле `float` превращается как обычно.
* Обращение к несуществующему полю — ошибка выполнения; `skrumi check` и редактор
  проверяют имя типа и число значений в `Point(...)`.
* Ссылки — как у массивов: присваивание и передача в функцию дают ту же структуру,
  `copy(p)` — независимую копию со всеми вложенными полями, `==` сравнивает поля.
* `json_value(a)` даёт `{"x":3,"y":4}`.

### Методы

Функция, объявленная внутри `struct`, — метод. Его вызывают через точку, а внутри
метода `this` — значение, у которого он вызван. Поля читаются и меняются через
`this.поле`.

```cpp
struct Counter {
    string name;
    int value = 0;

    void add(int step) {
        this.value += step;
    }

    bool reached(int limit) {
        return this.value >= limit;
    }

    string show() {
        return "${this.name}: ${this.value}";
    }
}

Counter clicks = Counter("клики");
clicks.add(3);
clicks.add(2);
print(clicks.show(), clicks.reached(5));   // клики: 5 true
```

* Метод меняет саму структуру, а не копию: структуры передаются по ссылке.
* Методы, как и функции, могут вызывать друг друга (`this.show()`), принимать и
  возвращать структуры, в том числе своего типа.
* Имя метода не может совпадать с именем поля. Число аргументов проверяется так же,
  как у функций; `this` в него не входит.
* Если в поле лежит функция (`func`), её тоже вызывают через точку, но без `this`.
  У поля `func` нет пустого значения, поэтому функцию нужно передать при создании
  (или объявить поле `func?`, тогда по умолчанию в нём `null`):

```cpp
struct Button {
    string label;
    func on_click;
}
Button ok = Button("OK", () => print("нажато"));
ok.on_click();
```

* У словаря через точку вызывается функция, лежащая по ключу: `handlers.save()`.
* Результат любого выражения, если это функция, можно вызвать сразу:
  `make_adder(1)(2)`, `handlers["save"]()`.
* `skrumi check` и редактор знают поля и методы структуры: сообщают о несуществующем
  поле или методе и о неверном числе аргументов, а после `имя.` предлагают поля и
  методы.

### Перечисления: enum

`enum` объявляет тип с фиксированным набором значений. Значение пишется как
`Имя.Значение`, у каждого есть `.name` (имя текстом) и `.value` (номер по порядку
с 0 или значение, заданное явно — целое число или строка).

```cpp
enum Direction { North, East, South, West }
enum Status { Active = "active", Blocked = "blocked" }
enum Priority { Low = 1, Normal, High = 10 }   // Normal = 2

Direction heading = Direction.East;
print(heading, heading.name, heading.value);    // East East 1
print(Status.Blocked.value, Priority.Normal.value);

string arrow(Direction where) {
    switch (where) {
        case Direction.North: return "↑";
        case Direction.South: return "↓";
        default: return "↔";
    }
}
print(arrow(heading));

for (name, item in Direction) {
    print(name, item.value);
}
```

* Имя перечисления — тип: переменные, параметры, поля и результаты функций типа
  `Direction` принимают только его значения. Строка `"East"` — не значение
  `Direction`: это ошибка `Type Error`.
* `print` и интерполяция показывают имя значения, `json_value` — имя строкой.
  `type_of(heading)` — `"Direction"`.
* Значения сравниваются `==` и `!=` и работают в `switch`.
* Поле или переменная типа перечисления без значения получает первое значение.
* Само имя `Direction` — неизменяемый словарь «имя → значение»: по нему можно пройти
  циклом, `size(Direction)` — число значений. Изменить значения или имя нельзя.
* Перечисление, как и структура, объявляется на верхнем уровне и доступно выше
  строки объявления. `skrumi check` сообщает о несуществующем значении
  (`Direction.Up`), редактор после `Direction.` предлагает значения.

## 11. Модули: using и include

```cpp
using string;   // модуль стандартной библиотеки
using json;
print(upper("fox"), json_quote("лис"));
```

`include("путь/к/файлу.skm");` подключает свой файл по пути.

Поиск `using имя;`: сначала стандартные модули на диске, затем встроенная
стандартная библиотека, затем обычные файлы проекта. Поддерживается только `.skm`.
Поиск учитывает каталог импортирующего файла, рабочий каталог, `SKRUMI_HOME`
и `SKRUMI_HOME/std`. Ошибка найденного модуля передаётся вызывающей программе.

Файл `arrays.skm` рядом с программой не подменяет стандартный `using arrays;`.
Явный `include("arrays.skm");` ищет указанный файл без подстановки расширения.
Явные пути `std/...` доступны из встроенных ресурсов, если файла на диске нет.
Повторный импорт одной канонической идентичности не инициализирует модуль заново.
[Перенос старых программ](docs/MIGRATION.md).

* Подключение выполняет только объявления модуля: функции, переменные, массивы и
  вложенные `using`/`include`. Остальные инструкции верхнего уровня модуля
  (например, демонстрационный вызов `main();`) пропускаются.
* Модуль загружается один раз за время работы программы, даже если подключён
  несколько раз или по кругу.
* Всё объявленное в модуле попадает в общее пространство имён программы. Функция,
  объявленная позже с тем же именем, заменяет прежнюю; переменную с уже занятым
  именем объявить нельзя.

### Псевдоним модуля: using ... as

`using модуль as имя;` подключает модуль как обычно и вдобавок создаёт переменную
`имя`, через которую функции и переменные модуля доступны с точкой. Так видно, из
какого модуля взята функция, а вызов через псевдоним не собьётся, даже если в
программе позже появится своя функция с тем же именем.

```cpp
using math as m;
using arrays as arr;

float side = m.hypot(3, 4);
print(side, m.PI, arr.sum([1, 2, 3]));

int hypot(int a) { return a; }   // своя функция с тем же именем
print(m.hypot(6, 8));            // 10: псевдоним по-прежнему ведёт в модуль
```

* Через псевдоним доступны функции и переменные, объявленные в самом модуле, и
  встроенные функции: `m.sqrt(2)` — то же, что `sqrt(2)`. Автодополнение после `m.`
  предлагает только имена модуля.
* Переменные модуля через псевдоним — их значения на момент подключения: для
  констант вроде `m.PI` это то, что нужно; массивы и словари общие с модулем.
* Псевдоним — глобальная константа (`type_of(m)` — `map`): ни его, ни его содержимое
  изменить нельзя, имя не должно быть занято.
* `skrumi check` и редактор проверяют имена и число аргументов после псевдонима, а
  после `m.` предлагают функции и переменные модуля.

## 12. Встроенные функции

Встроенные функции доступны без `using`. В таблицах `[тип имя]` — необязательный
параметр, `тип имя...` — любое число аргументов. `number` означает `int` или
`float`, `any` — значение любого типа. Аргументы проверяются по сигнатуре: неверное
число или тип аргумента — ошибка с именем параметра.

Функции с префиксами (`str_`, `fs_`, `os_`, `json_` и т. п.) — основа модулей
стандартной библиотеки, которые дают к ним короткие имена. Их можно вызывать и
напрямую.

### Ввод и вывод

| Функция | Описание |
|---|---|
| `print(any values...) -> void` | печатает значения через пробел и переводит строку |
| `input([string prompt]) -> string` | читает строку; в конце ввода — пустая строка |
| `getch() -> string` | одна клавиша из терминала без Enter и эха |
| `kbhit() -> bool` | есть ли нажатая клавиша в буфере терминала |
| `wait(int milliseconds) -> void` | пауза |
| `exit([int code]) -> void` | завершает программу с кодом возврата (по умолчанию 0) |
| `fail(string message) -> void` | останавливает программу с ошибкой выполнения и этим сообщением |
| `assert(bool condition, [string message]) -> void` | ошибка `Assertion failed`, если условие ложно |
| `assert_equal(any actual, any expected, [string message]) -> void` | ошибка с обоими значениями, если они не равны; числа по величине, контейнеры по содержимому |

### Массивы

| Функция | Описание |
|---|---|
| `size(any value) -> int` | число элементов массива или длина строки в **байтах** |
| `copy(any value) -> any` | независимая копия массива, словаря или структуры со всем вложенным |
| `get(array items, int index) -> any` | элемент по индексу |
| `set(array items, int index, any value) -> void` | запись элемента |
| `push(array items, any value) -> void` | добавить в конец |
| `pop(array items) -> any` | удалить и вернуть последний элемент |
| `insert(array items, int index, any value) -> void` | вставить перед `index` (`index == size` — в конец) |
| `remove_at(array items, int index) -> any` | удалить элемент и вернуть его |
| `resize(array items, int size) -> void` | изменить размер; новые элементы равны 0 |
| `array_sort(array items, [func before]) -> void` | сортировка на месте: все числа или все строки; с `before(a, b)` — в порядке, который задаёт функция |
| `array_reverse(array items) -> void` | обратный порядок на месте |
| `array_index_of(array items, any value) -> int` | индекс первого равного элемента или -1 |
| `array_copy(array items) -> array` | независимая копия, как `copy` |
| `array_slice(array items, int start, [int end]) -> array` | срез; отрицательные индексы — с конца |
| `array_map(array items, func transform) -> array` | новый массив из `transform(item)` |
| `array_filter(array items, func keep) -> array` | элементы, для которых `keep(item)` вернула `true` |
| `array_reduce(array items, func combine, any initial) -> any` | свёртка: `combine(result, item)`, начиная с `initial` |
| `array_find(array items, func matches) -> int` | индекс первого подходящего элемента или -1 |
| `array_any(array items, func matches) -> bool` | подходит ли хотя бы один элемент |
| `array_all(array items, func matches) -> bool` | подходят ли все (для пустого массива — `true`) |

`array_index_of` сравнивает числа по величине, остальное — по тексту, поэтому число
`5` находится и по строке `"5"`.

Функции, которые принимают `func`, вызывают её для каждого элемента по порядку.
`keep`, `matches` и `before` обязаны возвращать `bool`. Сортировка с `before`
устойчива: равные элементы сохраняют исходный порядок.

```cpp
array prices = [120, 45, 300, 80];
array cheap = array_filter(prices, p => p < 100);
array labels = array_map(cheap, p => "${p} ₽");
int total = array_reduce(prices, (sum, p) => sum + p, 0);
array_sort(prices, (a, b) => a > b); // по убыванию
print(labels, total, prices, array_any(prices, p => p > 250));
```

### JSON

| Функция | Описание |
|---|---|
| `json_get(string json, string path) -> string` | значение по пути |
| `json_count(string json, string path) -> int` | размер массива или объекта; -1, если там не контейнер |
| `json_type(string json, string path) -> string` | `object`, `array`, `string`, `number`, `bool`, `null` или пустая строка |
| `json_escape(string text) -> string` | экранирование для вставки внутрь JSON-строки |
| `json_value(any value) -> string` | значение Skrumi как JSON: строка в кавычках, массив — JSON-массив, словарь и структура — объект |
| `json_decode(string json) -> any` | JSON целиком: объект — `map`, массив — `array`, целое — `int`, дробное — `float`, `null` — `null`; текст, который не является JSON целиком (например, `tru` или `[1, 2`), — ошибка, её можно перехватить `try` |
| `json_set(string json, string path, any value) -> string` | новый документ со значением по пути |
| `json_set_raw(string json, string path, string raw_json) -> string` | то же, но значение — готовый JSON |
| `json_valid(string json) -> bool` | корректен ли документ |

Путь состоит из ключей объектов и индексов массивов через точку:
`message.chat.id`, `items.0.name` (можно и `items[0].name`). Пустой путь — весь
документ. Строки декодируются, включая `\uXXXX` и суррогатные пары emoji; объект
или массив возвращается как JSON-текст; отсутствующий путь даёт пустую строку.
Некорректный JSON не вызывает ошибку, а просто не содержит значения.

`json_set` строит документ по шагам и сам экранирует строки, поэтому собирать JSON
склейкой строк не нужно. Пустой документ считается `{}`, недостающие ключи
создаются, индекс, равный длине массива, добавляет элемент в конец:

```cpp
string user = json_set("", "name", "Лис \"Рыжий\"");
user = json_set(user, "stats.age", 3);
user = json_set(user, "tags", ["быстрый", "хитрый"]);
string list = json_set_raw("[]", "0", user);
print(list); // [{"name":"Лис \"Рыжий\"","stats":{"age":3},"tags":["быстрый","хитрый"]}]
```

### Веб и шаблоны

| Функция | Описание |
|---|---|
| `template_render(string template, string json) -> string` | HTML-шаблон, заполненный данными JSON |
| `html_escape(string text) -> string` | экранирование `& < > " '` для вставки в HTML |
| `url_encode(string text) -> string`, `url_decode(string text) -> string` | кодирование `%XX` для URL и форм |

Шаблоны похожи на Mustache:

| Запись | Результат |
|---|---|
| `{{путь}}` | значение по пути, HTML экранируется |
| `{{{путь}}}` | значение без экранирования |
| `{{#each путь}}...{{/each}}` | повтор для каждого элемента массива (или значения объекта); внутри `{{.}}` — элемент, `{{@index}}` — номер, `{{@key}}` — ключ |
| `{{#if путь}}...{{else}}...{{/if}}` | условие: `false`, `null`, `0`, `""`, `[]` и `{}` ложны |
| `{{! текст}}` | комментарий |

Внутри `each` путь ищется сначала в элементе, затем во внешних данных.

```cpp
string data = json_set("", "title", "Звери");
data = json_set(data, "animals", ["лис", "волк"]);
string page = template_render("<h1>{{title}}</h1><ul>{{#each animals}}<li>{{@index}}. {{.}}</li>{{/each}}</ul>", data);
print(page);
```

## 14. Ошибки и коды возврата

Ошибка останавливает программу, печатает сообщение в stderr и завершает процесс с
кодом `1`. Сообщение начинается с файла и строки, где случилась ошибка, — и в
программе из нескольких файлов это тот файл, где она произошла на самом деле:

```text
Skrumi: lib/prices.skm:12: Type Error: argument 'text' of str_upper() must be string, got 'int'
```

Путь пишется относительно рабочего каталога; с переменной окружения
`SKRUMI_ABSOLUTE_PATHS=1` — полностью (так делает кнопка запуска в VS Code).

| Вид | Когда возникает |
|---|---|
| `Syntax Error` | текст программы не разбирается: пропущенная `;`, скобка, неизвестный символ |
| `Type Error` | значение не того типа: в переменной, аргументе, условии, операторе |
| `Runtime Error` | деление на ноль, выход за границы массива, переполнение `int`, глубина рекурсии |
| `Module Error` | модуль или файл `include` не найден |
| `Environment Error` | не задан обязательный секрет |
| `HTTP Server Error`, `Graphics Error` | неверные параметры сервера или окна |

`exit(code)` завершает программу с указанным кодом без сообщения, `fail(message)` —
с ошибкой `Runtime Error` и вашим сообщением. Если обработчик HTTP-запроса
завершается ошибкой, сервер отвечает `500`, пишет ошибку в stderr и продолжает работу.

### try, catch, finally, throw

Ошибку можно перехватить и продолжить работу. В `catch` переменная получает текст
ошибки — тот же, что был бы напечатан (`Runtime Error: Division by zero`), для
`throw` — ровно ваше сообщение. `finally` выполняется всегда: после успешного `try`,
после `catch`, при `return`, `break`, `continue` и `exit` изнутри.

```cpp
string read_config(string path) {
    if (!fs_exists(path)) {
        throw "нет файла настроек: " + path;
    }
    return read_file(path);
}

string text = "";
try {
    text = read_config("settings.json");
} catch (string error) {
    print("работаем по умолчанию:", error);
} finally {
    print("проверка настроек закончена");
}
```

* Перехватываются ошибки выполнения всех видов: `Runtime Error`, `Type Error`,
  ошибки модулей, сети, файлов и `throw`. `exit()` не перехватывается.
* `catch (error)` — короткая запись `catch (string error)`; без скобок — `catch { ... }`,
  если текст ошибки не нужен. `catch` или `finally` можно опустить, но не оба.
* `throw` принимает любое значение и делает из него текст: `throw 404;`.
  Внутри `catch` ошибку можно выбросить дальше: `throw error;`.
* Ошибка, которую ничто не перехватило, завершает программу, как раньше.

```cpp
int parse_age(string text) {
    if (!is_number(text)) {
        fail("возраст должен быть числом: " + text);
    }
    return to_int(text);
}
print(parse_age("7"));
```

`skrumi check` находит многие ошибки без запуска: синтаксис, необъявленные
переменные и функции, неверное число аргументов (в том числе у встроенных функций),
`return` не на своём месте, отсутствующие модули. Проверка учитывает весь проект:
если `main.skm` подключает `utils.skm` и `render.skm`, функции и переменные одного
из них известны в другом (см. [раздел 21](#21-редакторы-и-языковой-сервер)).

## 15. Командная строка

```bash
skrumi program.skm [аргументы...]   # запуск; аргументы доступны через os_args()
skrumi check program.skm            # проверка без запуска
skrumi build program.skm [-o app]   # standalone-приложение
skrumi test [--filter текст] [пути] # тесты: функции test_ в файлах *_test.skm
skrumi fmt [--check] [пути]         # оформление исходников: отступы, пустые строки, пробелы
skrumi disasm program.skm           # байткод программы и её функций
skrumi debug-adapter                # отладчик для редакторов (DAP через stdin/stdout)
skrumi debug-adapter --connect host:port   # то же по TCP, программа остаётся в своём терминале
skrumi --version                    # версия
skrumi help                         # справка по всем командам (также --help и без аргументов)
skrumi help build                   # подробно об одной команде (также build --help)
skrumi --skrumi-licenses           # лицензии встроенных библиотек
```

**Байткод.** Программа выполняется так: парсер строит дерево, компилятор переводит
каждую функцию (при её первом вызове) и верхний уровень программы в байткод —
команды регистровой виртуальной машины, — а виртуальная машина их выполняет.
`skrumi disasm` печатает этот байткод: номер строки исходника, номер команды,
команду и её регистры. Сначала перечислены регистры переменных (параметры первыми)
и регистры чисел, с которыми функция считает.

```text
$ skrumi disasm fib.skm
...
fib(): 9 instructions, 6 registers (1 variables)
    r0 = n
    r4 = 2
    r5 = 1
5        0  compare      if not r0 < r4 -> 2
6        1  return       r0
8        2  sub          r2 r0 r5
         3  call         r2 = fib(r2)
         4  sub          r3 r0 r4
         5  call         r3 = fib(r3)
         6  add          r1 r2 r3
         7  return       r1
9        8  return-void
```

`skrumi check` печатает проблемы в формате `файл:строка:столбец: error: текст` и
завершается кодом `1`, если есть хотя бы одна ошибка; предупреждения код не меняют.

**Тесты.** `skrumi test` находит файлы `*_test.skm` (в текущей папке и ниже, без
скрытых папок, `build*` и `node_modules`, или в указанных файлах и папках) и
вызывает в каждом функции `test_...()` без параметров. Каждый тест выполняется в
свежей программе: верхний уровень файла запускается заново, поэтому глобальные
переменные одного теста не влияют на другой. Тест проходит, если закончился без
ошибки; `assert`, `assert_equal` и любые ошибки выполнения его проваливают с файлом и
строкой. Код возврата — `1`, если провалился хоть один тест.

```cpp
// math_test.skm
int add(int a, int b) {
    return a + b;
}

void test_add() {
    assert_equal(add(2, 3), 5);
    assert_equal([add(1, 1)], [2], "массивы сравниваются по содержимому");
}

void test_error_is_caught() {
    bool failed = false;
    try {
        array items = [1];
        int x = items[5];
    } catch (e) {
        failed = true;
    }
    assert(failed, "выход за границы массива — ошибка");
}
```

```text
$ skrumi test
math_test.skm
  ok   test_add (0.3 ms)
  ok   test_error_is_caught (0.2 ms)
2 tests: 2 passed, 0 failed
```

**Оформление.** `skrumi fmt` приводит файлы `.skm` к единому виду: четыре пробела на
уровень `{}`, `[]` и `()`, `case` на уровень выше своих операторов, без пробелов в
конце строк и табуляций в отступах, не больше одной пустой строки подряд, переводы
строк LF и перевод строки в конце файла. Сам код не переписывается, поэтому
оформление не может изменить поведение программы; выравнивание продолжения строки
под скобкой сохраняется. `--check` ничего не меняет и завершается кодом `1`, если
какой-то файл оформлен иначе, — удобно для CI. То же оформление делает команда
«Форматировать документ» в редакторе.

Код возврата запуска: `0` — успех, `1` — ошибка, либо значение, переданное в `exit`.

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `SKRUMI_HOME` | каталог установки; модули ищутся в нём и в `SKRUMI_HOME/std` |
| `SKRUMI_LOG_LEVEL` | порог логов: `debug`, `info` (по умолчанию), `warn`, `error`, `off` |
| `SKRUMI_CA_BUNDLE` | доверенные CA для HTTPS: путь к PEM, `embedded` или `system` |
| `SKRUMI_ABSOLUTE_PATHS` | непустое значение — полные пути файлов в сообщениях об ошибках |

## 16. Окружение, .env и логирование

При запуске исходника `skrumi app.skm` сначала читается `.env` рядом со скриптом,
а если его нет — `.env` текущего каталога. Уже заданные переменные окружения имеют
приоритет. Standalone-приложения `.env` не читают.

```dotenv
TELEGRAM_BOT_TOKEN=replace_me
SKRUMI_LOG_LEVEL=debug
```

```cpp
using env;
using log;
string token = env_default("TELEGRAM_BOT_TOKEN", "");
if (token == "") {
    warn("токен не задан");
}
int port = to_int(env_default("PORT", "8080"));
info("порт " + port);
```

* `env(name)` — значение или пустая строка;
* `secret(name)` — обязательное значение: если переменная не задана или пуста,
  программа завершается с ошибкой `Environment Error`;
* `env_default(name, fallback)` — значение или `fallback`;
* `set_env(name, value)` — задать переменную для текущего процесса.

Логи `debug`, `info`, `warn`, `error` пишутся в stderr с префиксами `[DEBUG]`,
`[INFO]`, `[WARN]`, `[ERROR]`. Уровень ниже порога `SKRUMI_LOG_LEVEL` не выводится.
Файлы `.env` исключены из Git; публичный шаблон — `.env.example`.

## 17. HTTP-клиент и доверенные CA

```cpp
using http;
using json;
using log;

string answer = http_get("https://api.github.com/repos/SkrinVex/Skrumi");
if (http_ok()) {
    print(json_path(answer, "full_name"));
} else {
    warn("статус " + http_status());
}

string created = http_post_json("https://httpbin.org/post", "{\"name\":\"лис\"}");
print(http_status(), size(created));
```

* Функции возвращают тело ответа при **любом** коде статуса; код последнего
  запроса — `http_status()`, проверка успеха — `http_ok()`.
* При сетевой ошибке или ошибке TLS возвращается пустая строка, `http_status()`
  равен `0`, причина печатается в stderr как `[HTTP ERROR]`. URL и тело запроса в
  сообщение не попадают: в них часто бывают токены.
* `content_type` по умолчанию `application/json`. Ответ ограничен 16 МиБ,
  подключение — 10 секундами, весь запрос — 35 секундами. Перенаправления
  выполняются только на `http` и `https`.

HTTPS всегда проверяет цепочку сертификатов и имя сервера. По умолчанию
используется встроенный набор публичных CA Mozilla, поэтому отдельный пакет
сертификатов не нужен. `SKRUMI_CA_BUNDLE` меняет источник:

- путь к PEM-файлу — свой набор доверенных CA;
- `embedded` — встроенный набор (по умолчанию);
- `system` — хранилище операционной системы.

На Linux, если `SKRUMI_CA_BUNDLE` не задан, учитывается `SSL_CERT_FILE`. Ошибочный
путь приводит к ошибке проверки TLS, а не к отключению проверки. Происхождение и
обновление встроенного набора описаны в [resources/ca](resources/ca/README.md).

## 18. HTTP- и HTTPS-сервер

Модуль `server` позволяет написать сайт или API целиком на Skrumi: маршруты с
параметрами, статические файлы, HTML-шаблоны, формы, загрузку и скачивание файлов,
cookies, перенаправления и CORS.

```cpp
using server;
using json;

void home() {
    string data = json_set("", "user", cookie("user"));
    respond_html(template_render("<h1>Привет, {{#if user}}{{user}}{{else}}гость{{/if}}!</h1>", data));
}

void show_user() {
    string id = param("id");
    string tab = query_param("tab");
    respond(json_set(json_set("", "id", id), "tab", tab));
}

void login() {
    set_cookie("user", form("name"), "Path=/; Max-Age=86400; HttpOnly; SameSite=Lax");
    redirect("/");
}

void report() {
    download("reports/2026.csv", "отчёт.csv");
}

void missing() {
    respond_as(404, "<h1>Страница не найдена</h1>", "text/html; charset=utf-8");
}

static_files("/static", "public");
get("/", "home");
get("/users/:id", "show_user");
post("/login", "login");
get("/report", "report");
not_found("missing");
access_log(true);
listen(8080);
```

Полный пример сайта из нескольких файлов — [examples/website](examples/website):
гостевая книга с шаблонами, статикой, формой, cookies, загрузкой и скачиванием
файлов и JSON API.

### Маршруты

`get`, `post`, `put`, `patch`, `delete` и `route(method, path, handler)` связывают
метод и путь с обработчиком — функцией без параметров. Её передают как значение
(`get("/", home)`), лямбдой (`get("/ping", () => { respond("pong"); })`) или именем
строкой (`get("/", "home")`). Функцию, указанную по имени, ищут в момент запроса,
поэтому её можно объявить и после маршрута.

* `:имя` совпадает с одной частью пути, `*имя` в конце — с остатком пути (может быть
  пустым): `/users/:id`, `/files/*path`. Значение читает `param(name)`, оно уже
  декодировано из `%XX`.
* Точный путь проверяется раньше шаблонов, шаблоны — в порядке регистрации.
  Повторная регистрация того же метода и пути заменяет обработчик.
* Завершающий `/` не важен: `/about` и `/about/` — один путь.
* Маршрут GET отвечает и на HEAD (заголовки без тела).
* Если путь есть, но для другого метода, ответ `405` с заголовком `Allow`.

### Запрос

| Функция | Что возвращает |
|---|---|
| `method()`, `path()`, `client_ip()` | метод, декодированный путь, IP клиента |
| `query()` | query-строка как пришла, без `?` |
| `query_param(name)` | параметр query-строки, декодированный |
| `param(name)` | параметр из шаблона пути |
| `form(name)` | поле HTML-формы: `application/x-www-form-urlencoded` или `multipart/form-data` |
| `body()` | тело как есть (например, JSON — читайте его `json_path`) |
| `header(name)` | заголовок без учёта регистра имени |
| `cookie(name)` | cookie, присланный браузером |
| `upload_name(field)` | исходное имя загруженного файла или пустая строка |
| `save_upload(field, path)` | сохраняет загруженный файл; `false`, если файла нет |

Не используйте имя загруженного файла как путь без проверки: в нём могут быть `../`.
Тело запроса ограничено 10 МиБ; `max_body_size(bytes)` меняет предел, больший запрос
получает `413`.

### Ответ

| Функция | Ответ |
|---|---|
| `respond(data)`, `respond_status(code, data)` | JSON (`application/json; charset=utf-8`) |
| `respond_html(html)`, `respond_text(text)` | HTML и обычный текст, код 200 |
| `respond_as(code, data, content_type)` | любой тип содержимого |
| `render(template_path, data)` | HTML из файла-шаблона и данных JSON (см. [шаблоны](#веб-и-шаблоны)) |
| `send_file(path)` | содержимое файла; тип по расширению; нет файла — `404` и `false` |
| `download(path, filename)` | файл для скачивания под указанным именем (кириллица допустима) |
| `redirect(url)` | перенаправление `302`; `server_redirect(url, 301)` — постоянное |
| `set_header(name, value)` | дополнительный заголовок |
| `set_cookie(name, value, options)` | cookie; `options` — атрибуты вроде `Path=/; Max-Age=3600; HttpOnly` |

Без вызова этих функций ответ — `200` с пустым телом. Значения заголовков не могут
содержать переводы строк: это защищает от подмены заголовков.

### Статические файлы, 404 и CORS

* `static_files(prefix, directory)` раздаёт файлы каталога: `static_files("/", "public")`
  отдаёт `public/app.js` по `/app.js`. Для каталога отдаётся `index.html`; адрес
  каталога без `/` на конце перенаправляется на адрес с `/`. Тип содержимого
  определяется по расширению (HTML, CSS, JS, JSON, изображения, шрифты, PDF, видео…).
  Скрытые файлы (например, `.env`) и выход за пределы каталога через `..` не отдаются.
  Маршруты проверяются раньше статических файлов.
* `not_found(handler)` вызывает вашу функцию, когда не подошёл ни маршрут, ни файл;
  статус ответа по умолчанию `404`. Без неё — JSON `{"error":"Not Found"}`.
* `allow_cors(origin)` добавляет заголовки CORS ко всем ответам и отвечает `204` на
  предварительные запросы `OPTIONS`; `"*"` разрешает любой домен.
* `access_log(true)` печатает в stderr строку о каждом запросе:
  `[HTTP] 127.0.0.1 GET /users/7 -> 200 (1 ms)`.

### Работа сервера

* `listen(port)` блокирует программу, пока обработчик не вызовет `stop_server()`.
  Сервер слушает `0.0.0.0` и обслуживает соединения по очереди: HTTP/1.0–1.1,
  `Content-Length`, до 64 КиБ заголовков; chunked-запросы не поддерживаются.
  Соединение ограничено 10 секундами, отдельная операция чтения или записи — 5 секундами.
* Ошибка в обработчике (включая `fail`) даёт ответ `500`, в stderr пишется ошибка с
  файлом и строкой, сервер продолжает работу.
* Все обработчики разделяют глобальные переменные программы: массив, объявленный на
  верхнем уровне, живёт между запросами.

**HTTPS.** `listen_tls(port, certificate, private_key)` включает встроенный TLS 1.2+
на Linux и Windows; reverse proxy не нужен. Аргументы — пути к PEM-файлам во время
запуска: сертификат (сначала сертификат сервера, затем промежуточные) и
незашифрованный приватный ключ. Отсутствующие, повреждённые или несовпадающие файлы
останавливают программу до открытия порта. Ошибка TLS-рукопожатия закрывает только
одно соединение. mTLS и автоматический выпуск сертификатов не реализованы; для смены
сертификата перезапустите сервер. Не храните ключи в исходниках.

```cpp
using server;
using env;

void health() {
    respond("ready");
}

get("/health", "health");
listen_tls(8443, secret("TLS_CERT_FILE"), secret("TLS_KEY_FILE"));
```

## 19. Standalone-приложения

```bash
skrumi build app.skm -o app      # Linux: ./app   Windows: app.exe
```

`skrumi build` упаковывает интерпретатор, программу и все её модули (`using` и
`include`, найденные рекурсивно, в том числе внутри функций и неисполненных веток) в
один исполняемый файл. Получателю не нужен установленный Skrumi, компилятор или
CMake. Аргументы командной строки приложения доступны через `os_args()`.

* Это упаковка со встроенным интерпретатором, а не компиляция в машинный код.
  Исходники хранятся внутри файла и могут быть извлечены — это не защита кода.
* `.env`, переменные окружения времени сборки и ресурсы (файлы для `read_file`) не
  встраиваются; секреты передавайте через окружение при запуске.
* Linux-сборка создаёт Linux-приложение, Windows-сборка — `.exe`; кросс-упаковки нет.
* Существующий выходной файл не перезаписывается.

`skrumi build game.skm --no-console` создаёт Windows GUI EXE без терминала;
`--console` выбирает консольный EXE (по умолчанию). У исходной и готовой программы
режим запуска переопределяют `--skrumi-console` / `--skrumi-no-console`.
`--skrumi-width N`, `--skrumi-height N`, `--skrumi-fullscreen` и
`--skrumi-windowed` задают начальные параметры окна. Это зарезервированные флаги:
остальные аргументы доступны через `os_args()`, а после `--` все аргументы
передаются буквально. `--skrumi-help` отдельно показывает справку runtime.
На Linux консольные флаги не меняют потоки и не создают терминал.

Полные правила, ограничения и примеры — [docs/LAUNCH.md](docs/LAUNCH.md).
Описание формата и упаковки — [docs/STANDALONE.md](docs/STANDALONE.md).

## 20. Нативная графика

`using graphics;` открывает нативное окно (X11/XWayland на Linux, Win32/GDI на
Windows) с программным 2D-рисованием, картинками PNG и BMP, встроенным пиксельным
шрифтом с кириллицей, вводом текста, клавиатурой, мышью с колесом и буфером обмена.
Окно может менять размер. Браузер и сторонние библиотеки не нужны. Модуль `ui`
добавляет кнопки, поля ввода, прокрутку и модальные окна, `sound` — звук.

**Картинки.** `load_image` читает PNG (все виды, в том числе с прозрачностью,
палитрой и чересстрочные) или BMP и возвращает номер картинки; окно для этого не
нужно, так что картинки удобно загрузить заранее. `draw_image` рисует картинку с её
прозрачностью, `draw_image_scaled` растягивает, `draw_image_alpha` делает её
полупрозрачной целиком, а `draw_image_part` рисует часть — кадр спрайта или плитку из
атласа. `image_pixel` и `image_alpha` читают пиксель, например для карты столкновений.

**Много объектов за кадр.** Сотни спрайтов или карта из тысяч плиток рисуются одним
вызовом: `draw_tiles` берёт массив номеров плиток и рисует только те, что видны в
окне, `draw_sprites` — массив троек «кадр, x, y», `draw_rects` — пятёрок «x, y,
ширина, высота, цвет». Это в разы быстрее, чем вызывать `draw_image_part` в цикле.

**Размер окна.** Нативное окно по умолчанию изменяет размер мышью;
`set_window_resizable(false)` запрещает изменение,
`set_window_size` меняет его из программы. В кадре после изменения
`window_resized()` истинно, а `window_width()` и `window_height()` возвращают новый
размер — самое время заново расставить элементы. При увеличении сохраняется
существующий холст, новая область чёрная; при уменьшении обрезанная часть теряется.
`set_window_fullscreen(true/false)` переключает нативный полноэкранный режим,
`window_fullscreen()` возвращает состояние. При выходе восстанавливаются размер
и положение. В Linux нужен EWMH-менеджер окон, подтверждение приходит при
`window_poll`. Перед `set_window_size` нужно выйти из fullscreen. В браузере
полноэкранный режим этого API не поддержан. Примеры — [docs/GRAPHICS.md](docs/GRAPHICS.md).

```cpp
using graphics;
using sound;

open_window(480, 320, "Лисья игра");
set_window_resizable(true);
int x = 40;
while (window_poll()) {
    if (key_pressed("ESCAPE")) {
        break;
    }
    if (key_down("RIGHT")) {
        x += 3;
    }
    if (key_pressed("SPACE")) {
        beep(660, 80);
    }
    clear_window(rgb(30, 60, 90));
    draw_rect(0, window_height() - 40, window_width(), 40, rgb(60, 140, 60));
    draw_circle(x, window_height() - 60, 20, rgb(255, 140, 0));
    present_window();
    wait(16);
}
close_window();
```

Картинку загружают так: `int hero = load_image("hero.png");`, рисуют —
`draw_image(hero, x, y);`, кадр 32×32 из атласа —
`draw_image_part(hero, frame * 32, 0, 32, 32, x, y, 32, 32);`.

```cpp
using graphics;
open_window(320, 200, "Skrumi");
while (window_poll()) {
```

### Интерфейс: кнопки, поля, диалоги

Модуль `ui` решает то, что в интерфейсе «из прямоугольников» сделать правильно
трудно: какой элемент получает щелчок, кто принимает ввод с клавиатуры и что
делает модальное окно.

* **Щелчок получает один элемент — верхний.** Кнопка, открывшая диалог, не нажимает
  в том же кадре кнопку диалога под курсором; перекрытый элемент не реагирует.
* **Модальное окно блокирует всё под собой:** кнопки, поля, списки под ним не
  подсвечиваются и не нажимаются, а фокус не уходит за его пределы.
* **Клавиатура принадлежит полю с фокусом.** Щелчок по полю даёт ему фокус и ставит
  курсор, Tab и Shift+Tab переходят между полями слоя, щелчок мимо полей снимает фокус
  (в диалоге фокус остаётся, пока не выбрано другое поле). Пока `ui_typing()` истинно,
  приложение не должно реагировать на горячие клавиши-буквы.
* **Поле ввода** принимает текст в любой раскладке (кириллицу, `/`, `.` и остальные
  символы), с Shift и Caps Lock, стирает Backspace и Delete с автоповтором, двигает
  курсор стрелками, Home и End, вставляет Ctrl+V и копирует Ctrl+C, прокручивает
  длинный текст.
* **Прокрутка.** `ui_scroll_begin` … `ui_scroll_end` — область с полосой прокрутки у
  правого края: колесо над ней, ползунок тянется мышью (и держится, даже если мышь
  ушла за полосу), щелчок по дорожке листает на страницу. Всё, что нарисовано внутри,
  обрезается по области, и щёлкнуть по строке, уехавшей за край, нельзя. Колесо
  получает самая внутренняя область под мышью; под модальным окном списки не
  прокручиваются.
* У каждого элемента свой постоянный `id`: по нему интерфейс узнаёт элемент в
  следующем кадре. Для строк списка подойдёт `"row" + i`.

```cpp
using graphics;
using ui;

open_window(480, 320, "Файлы");
bool asking = false;
string folder = "";
string status = "";
while (window_poll()) {
    clear_window(rgb(244, 246, 249));
    if (ui_button("new", 20, 20, 140, 30, "Новая папка")) {
        asking = true;
        folder = "";
        ui_focus("folder");
    }
    for (int i = 0; i < 3; i++) {
        if (ui_double_click("row" + i, 20, 70 + i * 26, 300, 24)) {
            status = "открыт файл " + i;
        }
        draw_text(24, 78 + i * 26, "файл " + i, 1, rgb(30, 35, 42));
    }
    if (!ui_typing() && key_pressed("Q")) {
        break;
    }
    if (asking) {
        ui_modal_begin(90, 90, 300, 150, "Новая папка");
        folder = ui_text_field("folder", 110, 140, 260, folder, "Имя папки");
        bool create = ui_primary_button("create", 190, 190, 90, 28, "Создать");
        if (create || (ui_focused("folder") && key_pressed("ENTER"))) {
            status = "создана " + folder;
            asking = false;
        }
        if (ui_button("cancel", 290, 190, 80, 28, "Отмена") || key_pressed("ESCAPE")) {
            asking = false;
        }
        ui_modal_end();
    }
    draw_text(20, 290, status, 1, rgb(90, 96, 104));
    present_window();
    wait(16);
}
close_window();
```

Для своих элементов используйте `ui_click` и `ui_hover` вместо проверки
`key_pressed("MOUSE_LEFT")` и координат мыши: только они учитывают слои и модальные
окна. Цвета элементов задают переменные модуля `UI_ACCENT`, `UI_TEXT`, `UI_BORDER`,
`UI_FIELD`, `UI_BUTTON`, `UI_BUTTON_HOVER`, `UI_PANEL`, `UI_BACKDROP`, `UI_TRACK`,
`UI_THUMB`, `UI_THUMB_ACTIVE`, а шаг колеса — `UI_SCROLL_STEP`; их можно присвоить до цикла.

Длинный список с прокруткой. Рисуются только видимые строки, поэтому каталог на
тысячи файлов не замедляет кадр:

```cpp
using graphics;
using ui;

open_window(420, 320, "Список");
array items;
for (int i = 0; i < 500; i++) {
    push(items, "строка " + i);
}
int scroll = 0;
int selected = 0;
int row = 24;
while (window_poll()) {
    clear_window(rgb(244, 246, 249));
    if (key_repeat("DOWN") && selected + 1 < size(items)) {
        selected++;
        scroll = ui_scroll_to(scroll, selected * row, (selected + 1) * row, 260);
    }
    scroll = ui_scroll_begin("items", 20, 30, 380, 260, scroll, size(items) * row);
    for (int i = scroll / row; i < size(items) && i * row - scroll < 260; i++) {
        int y = 30 + i * row - scroll;
        if (ui_click("item" + i, 20, y, 368, row)) {
            selected = i;
        }
        if (i == selected) {
            draw_rect(20, y, 368, row, rgb(205, 226, 252));
        }
        draw_text(28, y + 8, items[i], 1, rgb(30, 35, 42));
    }
    ui_scroll_end();
    present_window();
    wait(16);
}
close_window();
```

## 21. Редакторы и языковой сервер

`skrumi-lsp` — языковой сервер (LSP 3.17, stdio) для VS Code, Kate и Zed:
диагностика при вводе, автодополнение, подсказки при наведении, подсказки
параметров, переход к определению, поиск всех ссылок и переименование по всем
файлам программы, форматирование документа и символы документа. Он никогда не выполняет код
программы. Описания встроенных функций берутся из того же каталога, по которому
рантайм проверяет вызовы, а описания модулей — из комментариев `//!` и `///` в
`std/*.skm`.

**Проекты из нескольких файлов.** В программе Skrumi одно общее пространство имён:
если `main.skm` подключает `utils.skm` и `render.skm`, функция из `utils.skm` может
вызвать функцию из `render.skm` и прочитать глобальную переменную из `main.skm`.
Сервер и `skrumi check` анализируют файл вместе с остальными файлами его программы:
теми, что подключают его (прямо или через другие файлы), и всем, что подключают они.
Поэтому такие имена не подсвечиваются как необъявленные, а переход к определению
открывает нужный файл. Две разные программы, подключающие общую библиотеку, друг
друга не видят. Файлы ищутся в папке проекта (без скрытых папок, `build*` и
`node_modules`); несохранённые правки в открытых файлах учитываются сразу.

**Запуск из редактора.**

* VS Code: кнопка ▶ в заголовке редактора, `Ctrl+Alt+R`, команды «Skrumi: запустить
  программу», «проверить без запуска», «собрать приложение». Если программа состоит
  из нескольких файлов, выберите главный командой «Skrumi: сделать этот файл главным»
  — дальше ▶ запускает его из любого файла проекта. Ошибки выполнения и проверки
  попадают в панель «Проблемы» со ссылкой на файл и строку.
* Kate: «Сервис → Внешние инструменты → Skrumi» — запуск, проверка и сборка текущего
  файла с выводом в нижней панели.
* Zed: задачи «Skrumi: запустить / проверить / собрать» в `task: spawn`.

**Отладка.** `skrumi debug-adapter` — отладчик по протоколу DAP, общий для VS Code
(F5), Kate (плагин «Отладчик») и Zed (`debugger: start`):

* точки останова, в том числе условные (`i == 3`), по числу срабатываний (`5`, `>= 5`,
  `% 10`) и лог-точки (`i = {i}`) — вместо остановки печатают сообщение;
* шаги с заходом в функцию, через функцию и выход из неё, продолжение и пауза;
* стек вызовов, локальные и глобальные переменные, массивы по элементам, изменение
  значений прямо в панели переменных;
* выражения в наблюдении, при наведении и в консоли, где можно выполнять и операторы;
* остановка на операторе, где произошла ошибка выполнения, пока переменные на месте.

В VS Code программа работает в своём терминале, поэтому `input()` и графика работают
как при обычном запуске. Настройка и ограничения — в [docs/DEBUGGING.md](docs/DEBUGGING.md).

Настройка редакторов — в [docs/EDITORS.md](docs/EDITORS.md).

## 22. Встраивание в C++

Ядро собрано в статическую библиотеку `skrumi_core`; `skrumi` — тонкая обёртка над
ней.

```c++
#include <skrumi/Skrumi.h>
#include <iostream>

int main() {
    skrumi::InterpreterOptions options;
    options.arguments = {"--verbose"};       // то, что вернёт os_args()
    skrumi::Interpreter interpreter(options);

    interpreter.setGlobal("limit", "int", "10");
    skrumi::RunResult result = interpreter.runSource("int doubled = limit * 2;");
    if (result.success) {
        std::cout << interpreter.getGlobal("doubled").text() << std::endl;   // 20
    } else {
        std::cerr << result.errorMessage << std::endl;
    }
    return interpreter.runFile("script.skm").exitCode;
}
```

* `skrumi::Interpreter` — экземпляр рантайма со своими глобальными переменными,
  функциями и загруженными модулями; экземпляры независимы друг от друга.
* `skrumi::InterpreterOptions`: `skrumiHome` (каталог модулей), `loadDotEnv` (читать ли
  `.env` в `runFile`), `sources` (свой `SourceProvider` вместо файловой системы),
  `arguments` (аргументы для `os_args`), `windowWidth`/`windowHeight` (0 сохраняет
  размер из программы), `windowFullscreen` (начальный полноэкранный режим).
* `skrumi::RunResult`: `success`, `exitCode` (1 при ошибке или код из `exit`),
  `errorMessage`.
* `interpreter.setGlobal(имя, тип, текст)` объявляет глобальную переменную типа `int`,
  `float`, `bool` или `string` из текста (`"10"`, `"2.5"`, `"true"`); текст, который не
  подходит к типу, — ошибка `Type Error`.
* `skrumi::Value` — значение Skrumi, 16 байт. Вид — `kind()`
  (`Value::Kind::Int`, `Float`, `Bool`, `String`, `Array`, `Map`, `Struct` или `Void`);
  содержимое — `asInt()`, `asFloat()`, `asBool()`, `str()` для строки, `ref()` для
  массива, словаря или структуры (их элементы в `ref()->items`). `text()` даёт число,
  `bool` или строку текстом, `typeName()` — имя типа, как `type_of()`. Новые значения:
  `Value::integer(42)`, `Value::real(2.5)`, `Value::boolean(true)`,
  `Value::string("Лис")`. Копия значения не копирует ни текст, ни элементы: строки и
  контейнеры общие, со счётчиком ссылок. Значения принадлежат потоку интерпретатора.
* `skrumi::builtinCatalog()` — описание всех встроенных функций: имя, параметры,
  тип результата, документация.
* `skrumi::Lexer`, `skrumi::Parser`, `skrumi::SemanticAnalyzer` — разбор и
  статический анализ без выполнения.

Android 9+ поддерживается через NDK/JNI: AAR для Java/Kotlin, `SkrumiView` для
`graphics`/`ui`, экранный ввод, WAV/тоны, HTTP/TLS и упаковщик APK из `.skm`.
Нативная библиотека называется `libskrumi_android.so`; стандартные модули и CA
встроены. Экземпляры SDK выполняются последовательно на рабочем потоке, отменяются
через `cancel()` и закрываются через `close()`. Подробные примеры, сборка,
жизненный цикл и ограничения Android — в [docs/ANDROID.md](docs/ANDROID.md).
Android CI собирает четыре ABI и запускает instrumentation на эмуляторах x86_64
API 28/35. Все экземпляры SDK выполняются последовательно на общем потоке;
долгая программа задерживает другую до завершения или отмены.
Релизы также содержат APK игры raycaster из общего `examples/raycaster.skm`.
Проверки жизненного цикла Activity и [замеры передачи кадров](docs/ANDROID_PERFORMANCE.md)
дополняют тесты runtime; скорость на эмуляторе не приравнивается к скорости телефона.

## 24. Сборка и тесты

Нужны CMake 3.18+, компиляторы C и C++17; на Linux ещё pkg-config и заголовки XCB
(`libxcb1-dev libxau-dev libxdmcp-dev`). При первой конфигурации CMake скачивает
libcurl и Mbed TLS с проверкой SHA-256.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

**Версия** хранится только в файле `VERSION`. CMake передаёт её в `skrumi` и
`skrumi-lsp` и при каждой конфигурации сам проставляет её в манифесты расширений
VS Code и Zed. Без сборки то же делает `cmake -P cmake/Version.cmake`. Изменение
`VERSION` в ветке `master` запускает выпуск новой версии в GitHub Actions.

**Цифры на сайте** — версия, число встроенных функций, модулей и тестов в
`site/index.html` — руками не правятся. Их берёт из кода
`packaging/site_facts.py`: версию из `VERSION`, функции из каталога встроенных,
модули из `std/`, тесты из `ctest -N`. Скрипт запускает каждая сборка (цель
`site_facts`) и выкладка сайта, а одноимённый тест сообщает, если закоммичена
страница со старыми цифрами. Число модулей в README и руководстве по тестированию сверяется тем же `packaging/site_facts.py`. Число тестов на сайте относится к Linux CTest; браузерные проверки и Android instrumentation выполняются отдельно.

**Конструктор интерфейсов:** [Skrumi UI](https://skrinvex.github.io/Skrumi/builder/)
позволяет визуально собрать окно, настроить макеты телефона и ПК и экспортировать
обычную программу с `graphics` / `ui`. Во вкладке «Запуск» выполняется настоящий
WebAssembly-runtime. Проект сохраняется в браузере и переносится через JSON.
`layout.skm` генерируется из макета, а `main.skm` с обработчиками можно редактировать во вкладке «Код»: правки макета его не перезаписывают. Оба файла сохраняются в проекте и передаются в песочницу. Обратного построения макета из произвольного `.skm` нет.
Шаги работы, привязки и ограничения — [docs/BUILDER.md](docs/BUILDER.md).

**Песочница в браузере** (`site/playground/`, на сайте —
https://skrinvex.github.io/Skrumi/playground/) выполняет программу в браузере
посетителя: тот же интерпретатор, собранный Emscripten в WebAssembly, работает в
web worker. Страница останавливает программу через 10 секунд, ограничивает вывод
миллионом символов, память — 512 МБ. Функции уходят в рекурсию так же глубоко, как
в обычном Skrumi, а лямбды и методы — до 1000 уровней (стек браузера меньше
обычного). Окно `using graphics` рисуется на странице: программа с окном работает
сколько угодно, пока вызывает `window_poll()`, а клавиши, мышь и касания доходят до
неё в этот момент. Для таких программ страница загружает отдельную сборку с
Asyncify (`skrumi-graphics`), она примерно вдвое медленнее обычной. Сети, звука и
запуска процессов там нет — такие функции сообщают об этом ошибкой; файлы живут в памяти до конца запуска, `input()` читает строки из
поля «Ввод программы». Программа может состоять из нескольких файлов (вкладки над
редактором): запускается `main.skm`, остальные подключаются через `using` и `include`. Собрать её локально:

```bash
emcmake cmake -S . -B web -DCMAKE_BUILD_TYPE=Release
cmake --build web
cp web/skrumi*.js web/skrumi*.wasm web/skrumi*.js web/skrumi*.wasm site/playground/
node tests/web/test_playground.js site/playground   # примеры и ограничения
python3 -m http.server -d site                     # http://localhost:8000/playground/
```

Выкладка сайта собирает её сама; тот же тест запускает CI.

**Оптимизация при компоновке** (LTO) включена для сборки Release, если компилятор
её поддерживает; выключить — `-DSKRUMI_LTO=OFF`. Файл виртуальной машины
`src/core/Vm.cpp` в неё не входит: встроенные в цикл VM чужие функции увеличили бы
кадр каждого вызова и уменьшили допустимую глубину рекурсии.

Состав тестов описан в [tests/README.md](tests/README.md).

## Проверяемые файловые операции

Дополнение к `using fs;`. Старые `read_file`, `write_file`, `fs_copy` и другие
функции сохраняют прежние возвращаемые значения. Новые строгие функции при ошибке
выбрасывают исключение `System Error`; его можно обработать обычным `try/catch`.
Текст содержит операцию, путь и категорию/число системной ошибки. Некорректные
аргументы вызывают исключение до выполнения операции.

| Встроенная сигнатура | Функция модуля `fs` | Результат |
|---|---|---|
| `fs_read_checked(string path) -> string` | `read_checked(string path) -> string` | Полное содержимое файла, включая нулевые байты. Пустой файл — пустая строка; отсутствующий/недоступный файл — ошибка. Лимит 64 МиБ. |
| `fs_write_atomic(string path, string data) -> void` | `write_atomic(string path, string data) -> void` | Создаёт временный файл рядом с целью, полностью записывает и синхронизирует его, затем заменяет цель. Родитель должен существовать. |
| `fs_mkdtemp(string parent) -> string` | `make_temp_dir(string parent) -> string` | Создаёт уникальный каталог в существующем родителе; возвращает абсолютный путь. На POSIX права `0700`. Удаление — ответственность вызывающего кода. |
| `path_safe_join(string base, string relative) -> string` | `safe_join(string base, string relative) -> string` | Абсолютный путь внутри base. Запрещены абсолютный relative, `..`, `.`, пустые компоненты, обратный слеш, двоеточие и существующие ссылки. |

`safe_join` также запрещает управляющие символы, `*?"<>|`, компоненты с конечной
точкой/пробелом и имена устройств Windows (`CON`, `NUL`, `COM1` и другие) на всех
платформах: эти имена не являются безопасными переносимыми именами файлов.

Все четыре функции отклоняют пустые пути и встроенный NUL. Строгие операции
отклоняют символические ссылки в существующих компонентах пути, на Windows также
reparse points. Это **не sandbox**: проверка пути не исключает конкурентную подмену
каталога другим процессом. Используйте принадлежащие приложению каталоги без доступа
на запись посторонних пользователей. `safe_join` не резервирует путь и не создаёт
каталоги.

`write_atomic` заменяет файл целиком, включая его метаданные: на POSIX новый файл
имеет права `0600`. Она не предназначена для сохранения ACL или исполняемых прав
существующего файла. Данные синхронизируются через `fsync`/`FlushFileBuffers`;
на POSIX после rename также синхронизируется родительский каталог, на Windows
используется `MoveFileExW` с `MOVEFILE_WRITE_THROUGH`. При ошибке синхронизации
после замены новое содержимое уже может быть видно. Гарантии зависят от файловой
системы и накопителя; это не транзакция над несколькими файлами. Не заменяйте этим
API чужие файлы без проверки владения и ожидаемого содержимого.

В браузере `fs_write_atomic` вызывает контролируемую ошибку: виртуальная FS
Playground не гарантирует долговечность записи. Остальные операции работают только
в виртуальной файловой системе и не дают доступа к файлам компьютера. На Android
сохраняется существующее разрешение относительных путей через каталог приложения.

```cpp
using fs;
string staging = make_temp_dir(temp_dir());
try {
    string file = safe_join(staging, "состояние.json");
    write_atomic(file, "{\"stage\":\"prepared\"}");
    print(read_checked(file));
} catch (error) {
    print(error);
}
remove_tree(staging);
```

## ProgressBar, диалоги и управляемое закрытие

Компоненты `using ui;` написаны на Skrumi и используют тот же immediate-mode
рендерер, что и существующие кнопки и поля. Их нужно рисовать каждый кадр перед
`present_window()`. Геометрия задаётся в пикселях поверхности окна; автоматического
DPI-масштабирования и системного шрифта эти компоненты не добавляют.

| Сигнатура | Поведение |
|---|---|
| `ui_theme(bool dark) -> void` | Устанавливает светлую/тёмную палитру всех существующих `UI_*` цветов; акцент `#ef7b35`. По умолчанию до вызова сохраняется старая палитра. |
| `ui_progress_fraction(float value, float minimum, float maximum) -> float` | Нормализует значение в `0..1`, ограничивает выход за диапазон. `maximum <= minimum` — ошибка. |
| `ui_progress_bar(int x, int y, int width, int height, float value, float minimum, float maximum, bool percent) -> void` | Рисует определённый прогресс; проценты округляются вниз. При ширине/высоте меньше 3 ничего не рисует; текст рисуется, если помещается внутри с отступом 2 пикселя (для прежнего шрифта высота ≥11). |
| `ui_progress_busy(int x, int y, int width, int height, float phase) -> void` | Неопределённый прогресс: движущийся сегмент. phase — время/счётчик, полный период равен 2. Это не процент выполнения. |
| `ui_dialog(string id, string title, string message, string kind) -> string` | Модальный диалог текущего кадра. kind: `info`, `error`, `confirm`; другой вид — ошибка. Возвращает `pending`, `ok`, `yes`, `no`, `cancel`. Escape даёт `cancel`. |

Цвета ProgressBar: `UI_BORDER`, `UI_TRACK`, `UI_ACCENT`, `UI_TEXT`. Для собственного
стиля переопределите нужные переменные после `ui_theme`. Кнопки, поля, панели и
скроллбары используют ту же палитру. Диалог рисуется **последним** в кадре, поверх
основного интерфейса, до представления кадра. Он не запускает вложенный цикл событий
и не блокирует приложение; вызывающий код хранит состояние до получения ответа.
Длинное сообщение переносится по ширине карточки и прокручивается; явные переводы строк `\n` сохраняются.
Системный запрос закрытия не является нажатием кнопки диалога: приложение само
выбирает, отменить его или дождаться завершения операции.

| API `graphics` | Встроенный API | Поведение |
|---|---|---|
| `intercept_window_close(bool enabled) -> void` | `gfx_intercept_close(bool enabled) -> void` | Включает отложенное закрытие. По умолчанию выключено. Выключение при ожидающем запросе принимает запрос. |
| `window_close_requested() -> bool` | `gfx_close_requested() -> bool` | Ожидает ли запрос ответа приложения. `window_poll` при таком запросе продолжает возвращать true. |
| `cancel_window_close() -> void` | `gfx_cancel_close() -> void` | Сбрасывает запрос. Повторный вызов допустим. |

Повторные запросы объединяются в одно ожидающее состояние; обработчики не
вызываются рекурсивно. Win32 WM_CLOSE и X11 WM_DELETE_WINDOW (в том числе Alt+F4
через оконный менеджер) следуют этой модели. Уничтожение окна ОС нельзя отменить;
принудительное завершение процесса не является событием, на которое можно надёжно
ответить. `close_window()` по-прежнему закрывает без запроса и освобождает ресурсы.
В браузере это событие canvas runtime; оно не отменяет закрытие вкладки браузера.

Рабочий пример: [examples/progress.skm](examples/progress.skm), также доступный в
Playground. Он демонстрирует UI, а не установку или фиктивный прогресс файловых
операций. Standalone собирается существующей командой
`skrumi build examples/progress.skm -o progress`; на Windows можно добавить
`--no-console`.

UI Builder сохраняет ProgressBar в формате проекта 1 с полями `minimum`, `maximum`,
`progress`, `percent`. При импорте старого проекта они получают значения
`0`, `100`, `0`, `true`. Значение экспортируется как изменяемая переменная
`progress_<id>`. Поле проекта `theme` принимает `legacy`, `light`, `dark`;
отсутствующее поле означает `legacy`. Это тема создаваемого приложения, независимая
от темы самой страницы редактора. Произвольный пользовательский `main.skm`
сохраняется без перезаписи.

## Встроенные ресурсы standalone

`using resources;` — новый модуль на Skrumi (`std/resources.skm`). Ресурсы входят
в standalone только при явном `skrumi build main.skm --resources assets -o app`.
Каталог `assets` должен содержать только предназначенные для распространения данные:
все обычные файлы, включая скрытые, добавляются рекурсивно. Не помещайте туда секреты.
Символические ссылки и Windows reparse points запрещены. Ресурсы не извлекаются
автоматически, не выполняются и не открываются через текущий каталог.

| Встроенный API | Обёртка модуля | Контракт |
|---|---|---|
| `resource_list() -> array` | `resource_names() -> array` | Отсортированные имена ресурсов; пустой массив, если их нет. |
| `resource_read(string name) -> string` | `read_resource(string name) -> string` | Точные бинарные байты, включая NUL. Пустой ресурс возвращает пустую строку; отсутствующий — исключение Resource Error. |
| `fs_sha256(string path) -> string` | `file_sha256(string path) -> string` из `fs` | Потоковый SHA-256 обычного файла, 64 строчных hex-символа. Ошибки чтения и ссылки отклоняются. |

Имя ресурса — относительный ключ с `/`, например `payload/skrumi`. Абсолютные имена,
обратный слеш, двоеточие, пустые компоненты, `.` и `..` запрещены. Это не путь записи:
для размещения ресурса на диске приложение отдельно выбирает и проверяет назначение.
Лимиты: до 4096 ресурсов; общий сериализованный payload исходников, импортов и
ресурсов — не более 64 МиБ. `resource_read` возвращает ресурс целиком; не является
потоковым API. Запуск исходника и браузерный Playground не получают ресурсный каталог:
`resource_read` там выдаёт ошибку, а не читает файл из cwd. На Android провайдер
источников также не предоставляет standalone-ресурсы автоматически.

`fs_sha256` доступен на нативных платформах через уже используемую библиотеку Mbed TLS;
в WebAssembly выдаёт контролируемую ошибку недоступности. Проверяйте хеш после
размещения файла; хеш не обеспечивает неизменность файла после проверки и сам по себе
не подтверждает издателя. CRC standalone обнаруживает повреждение контейнера,
но не является криптографической подписью.

Формат контейнера v2 добавляет ресурсную таблицу; v1 по-прежнему читается. Программы
без ресурсов сохраняют v1. Старые runtime не обязаны читать v2; получатель standalone
использует runtime, уже находящийся внутри executable. Windows EXE нужно собирать
и проверять на Windows, Linux ELF — на Linux.

### Процессы с захватом вывода и отменой

`using os;` теперь предоставляет `array run_capture(string program, array args,
int timeout_ms)`: синхронный запуск без shell. Результат — массив
`[exit_code, stdout, stderr, timed_out, cancelled, truncated]`.
`args` содержит только строки, включая пустые; NUL запрещён. stdin читает EOF.
Тайм-аут — 1..3600000 мс. stdout и stderr независимо ограничены 16 МиБ;
при превышении данные продолжают считываться, но отбрасываются, `truncated=true`.
Ошибка запуска вызывает `Process Error`, ненулевой exit code возвращается как результат.

Для окон используйте неблокирующие встроенные функции:

- `int process_start(string program, array args, int timeout_ms)` — handle процесса.
- `bool process_poll(int handle)` — собрать доступный вывод, проверить тайм-аут;
  true при завершении. Вызывайте каждый кадр: проверка тайм-аута происходит при poll.
- `array process_result(int handle)` — тот же массив результата после завершения;
  ранний вызов вызывает ошибку. Повторное чтение разрешено до release.
- `void process_cancel(int handle)` — принудительно остановить процесс и его группу;
  затем продолжать poll до завершения. Повторная отмена допустима.
- `void process_release(int handle)` — освободить завершённый handle; незавершённый
  или неизвестный handle вызывает ошибку. Одновременно допускается 32 handle.

Linux использует группу процессов, Windows — Job Object. Потомки, самостоятельно
вышедшие из группы на POSIX, не контролируются. Оставшиеся дочерние процессы
останавливаются при уничтожении runtime. Это управление процессами, не sandbox.
Браузер и Android явно отклоняют эти API с `Process Error`.

```cpp
using os;
try {
    array result = run_capture("skrumi", ["--version"], 5000);
    print(result[0], result[1], result[2]);
} catch (string error) {
    print(error);
}
```

На POSIX runtime завершает принадлежащего ему лидера и исходную группу процессов;
переход лидера в другую группу не даёт права сигнализировать всей новой группе.
Ошибки явной отмены/тайм-аута сообщаются как `Process Error`. При уничтожении
runtime очистка выполняется по возможности и не ждёт бесконечно, если ОС отказала
в завершении. Это не sandbox: изменившие привилегии или покинувшие группу потомки
могут требовать управления средствами ОС. Встраивающий host не должен самостоятельно
reap-ить дочерние процессы, принадлежащие runtime.

### Строгие операции с каталогами

`bool fs_exists_checked(string path)` отличает отсутствующий путь (`false`) от
ошибок доступа (`System Error`). `void fs_mkdir_checked(string path, bool exclusive)`
создаёт один каталог: родитель должен существовать, `exclusive=true` запрещает
повторное создание. `void make_dirs_checked(string path)` из `using fs;` создаёт
родителей. Существующий обычный файл на месте каталога — ошибка.

`void fs_rename_checked(string from, string to)` перемещает файл или каталог
в пределах тома, отказывает при существующей цели. `void fs_remove_checked(string path)`
удаляет файл или пустой каталог; отсутствие допустимо. `array fs_list_checked(string path)`
возвращает отсортированные имена, ошибка не подменяется пустым массивом.
Все эти операции запрещают ссылки в пути и вызывают `System Error` при сбое.
На POSIX изменение имени синхронизирует родительские каталоги. После ошибки fsync
изменение уже может быть видимым. Проверки не исключают конкурентной подмены путей;
для rename проверка отсутствия цели на POSIX сама по себе не атомарна.

`void copy_checked(string source, string destination, bool overwrite)` из `using fs;`
копирует обычный файл до 64 МиБ через atomic write и сохраняет его права.
При `overwrite=false` существующая цель вызывает ошибку. Ошибка установки прав
возможна после записи файла. Прикладная программа должна исключать конкурентных писателей.

### Каталоги пользователя и архитектура

`string os_user_dir(string kind)` и `string user_directory(string kind)` из `using os;`
принимают `home`, `data`, `config`, `cache`, `state`. Возвращают абсолютный путь без
создания каталога. Linux использует XDG_DATA_HOME/CONFIG_HOME/CACHE_HOME/STATE_HOME,
только если значение абсолютное; иначе — `.local/share`, `.config`, `.cache`,
`.local/state` внутри home. Windows использует Known Folder Profile для home и
LocalAppData для остальных. Browser/Android вызывают контролируемый `System Error`.
`string os_arch()` и `string architecture()` возвращают архитектуру runtime:
`x86_64`, `arm64`, `x86`, `arm`, `wasm32` или `unknown`.

`int fs_lock(string path)` открывает/создаёт файл эксклюзивной блокировки без ожидания;
если он занят, выбрасывает `System Error`. Использует flock на POSIX и эксклюзивный
CreateFileW на Windows. `void fs_unlock(int handle)` снимает блокировку. Handle
принадлежит runtime; при его уничтожении блокировки снимаются ОС. Файл остаётся:
его нельзя удалять/заменять, пока возможны конкурирующие владельцы. Максимум 128
handle; неизвестный handle вызывает ошибку. В браузере fs_lock недоступен.

`string sha256_bytes(string data)` возвращает SHA-256 байтов строки (включая NUL)
в виде 64 строчных hex-символов, без файловой операции. Ошибки криптобиблиотеки и
вызов в браузере дают `System Error`. Это проверка целостности, не подпись издателя.

`int gfx_image_decode(string bytes)` и `int decode_image(string bytes)` из
`using graphics;` декодируют PNG/BMP из памяти, например
`decode_image(resource_read("logo.png"))`. Возвращают обычный image handle для
`draw_image_scaled`/`free_image`. Ошибки формата вызывают `Graphics Error`.
Работает в нативном и браузерном runtime; запись временного файла не требуется.

### Сохраняемый пользовательский PATH

`using env;`:

- `array user_path_plan(string directory, bool add)` возвращает план
  `[backend, destination, before, after]`, ничего не записывая. `directory` абсолютируется.
- `void user_path_validate(array plan)` проверяет форму снимков и разрешённую цель:
  HKCU `Path` или поддерживаемый конфигурационный файл shell текущего пользователя; некорректный
  план вызывает `Environment Error` до записи. `apply` и `removal` вызывают эту проверку сами.
- `void user_path_apply(array plan, bool reverse)` применяет план (`false`) или
  восстанавливает предыдущий снимок (`true`). Повторный вызов не дублирует запись.
  Если фактическое состояние отличается от обоих снимков, возникает `Environment Error`;
  посторонние изменения не перезаписываются.
- `array user_path_removal(array installed_plan, string directory)` планирует удаление
  только ранее добавленной записи, сохраняя текущие сторонние правки. План добавления
  без изменений не владеет существующей записью: его удаление тоже ничего не меняет.

Windows работает с HKCU Environment\\Path, сохраняет REG_SZ/REG_EXPAND_SZ и уведомляет
WM_SETTINGCHANGE. Сравнение путей нечувствительно к регистру и разделителю. Записи с
неразвёрнутыми `%VAR%` не приравниваются к развёрнутым путям. Linux добавляет помеченный
блок в `.bash_profile`, если он есть, иначе `.profile`; для SHELL=zsh — `.zprofile`.
Блок не дублирует путь в момент входа. Изменения действуют для **новых login-сессий**;
текущее окружение не изменяется. Для Fish добавляется помеченный блок с нативным
синтаксисом в `$XDG_CONFIG_HOME/fish/conf.d/skrumi-path.fish` (по умолчанию
`$HOME/.config/fish/conf.d/skrumi-path.fish`). Он действует для новых процессов Fish,
не дублирует существующий элемент PATH и участвует в том же механизме отката.
csh/tcsh пока не поддерживаются. Файлы окружения
systemd и конфигурация других shell не меняются. Недопустимые разделители пути
вызывают ошибку, shell-подстановка пользовательского пути не выполняется.

Планы содержат прежний текст профиля/PATH: храните их в пользовательском каталоге
с ограниченным доступом. Кооперативную блокировку вызывающая программа обеспечивает
через `fs_lock`. Проверка снимка и запись не атомарны относительно стороннего редактора
профиля/реестра; ошибка после записи/синхронизации может означать видимое изменение.

Низкоуровневые Windows API: `array env_user_snapshot(string name)` возвращает
`[present, expandable, value]` без раскрытия переменных;
`void env_user_compare_exchange(string name, array expected, array replacement)`
проверяет снимок, записывает/удаляет значение, выполняет RegFlushKey и уведомление.
`[false,false,""]` означает отсутствие. Ошибки — `Environment Error`, включая
вызов на других платформах. Это проверка перед заменой, не атомарный CAS ОС.

### Архивы USTAR

`array archive_extract(string bytes, string destination)` и
`array extract_archive(string bytes, string destination)` из `using fs;`
проверяют USTAR (без сжатия) и распаковывают его в **новый** каталог. Результат —
относительные имена извлечённых обычных файлов. Лимиты: 64 МиБ входных данных,
4096 записей. Поддерживаются обычные файлы и каталоги, права 000..777; запрещены
ссылки, устройства, setuid/setgid, GNU/PAX-расширения, traversal, повторяющиеся имена
и существующая цель. Проверяются checksum заголовков, длины и завершающие блоки
до создания каталога. Для проверки содержимого используйте `fs_sha256` и доверенный
manifest: checksum TAR не является криптографической проверкой.

При ошибке ввода-вывода (`System Error`) частичный каталог **сохраняется**;
используйте отдельный staging и собственный журнал. Форматные ошибки дают
`Archive Error`. Каталог назначения создаётся с правами 0700 на POSIX; ссылки в
его родителях не допускаются. Как и файловые API, распаковка не является sandbox
против конкурентной подмены каталогов. Browser сообщает о недоступности API.

`string ui_dialog_box(string id, int x, int y, int width, int height, string title,
string message, string kind)` — тот же неблокирующий модальный диалог с заданным
прямоугольником. Ответ и допустимые `kind` совпадают с `ui_dialog`; width/height
меньше 3 вызывают ошибку. Для читаемого содержимого используйте хотя бы 144×100.
UI Builder экспортирует этот API для диалогов и сохраняет обработчики в main.skm.

### Масштабируемые шрифты

`using graphics;` предоставляет `int load_font(string bytes)` (`gfx_font_load(bytes)`),
`void free_font(int font)` (`gfx_font_free(font)`),
`int font_text_width(int font, string text, int pixels)` (`gfx_font_width(font, text, pixels)`),
`void draw_font_text(int font, int x, int y, string text, int pixels, int color)`
(`gfx_font_text(font, x, y, text, pixels, color)`). TTF/OTF загружается из памяти, максимум 8 МиБ и 32 handle на
runtime; размер 8..96 пикселей, x/y обозначают верх строки. Ошибки формата,
размера и handle — `Graphics Error`. Метрики и сглаживание одинаковы в
Windows/Linux/Android/Web благодаря статически связанному FreeType 2.14.1.
Нет зависимости от установленных в ОС шрифтов. Поддерживаются Unicode glyphs
и переводы строк; shaping, kerning и bidi в этом API не реализованы.

`using ui;`: `void ui_set_font(int font, int pixels)` задаёт шрифт кнопок, полей,
флажков и диалогов. Handle 0 возвращает прежний пиксельный рендерер.
`int ui_text_width(string text)`, `int ui_text_height()` и
`void ui_draw_text(int x, int y, string text, int color)` используют выбранный шрифт.
Низкоуровневое поле:
`string gfx_ui_text_font(string id, int x, int y, int width, int height, string text,
int font, int pixels, int color)` возвращает отредактированный текст. Ширина курсора
и прокрутка вычисляются по метрикам шрифта. Ctrl+A выделяет всё, ввод заменяет
выделение, Ctrl+X вырезает. Старый `gfx_ui_text` сохраняет пиксельный формат.

FreeType добавлен ради переносимого сглаженного текста; необязательные библиотеки
compression/image/shaping отключены. Шрифт DejaVu Sans поставляется только как
ресурс установщика, а не в каждом runtime. Лицензия FreeType включена в `--licenses`,
лицензия шрифта — в `installer/assets/FONT-LICENSE.txt` и ресурсы установщика.

`array ui_wrap_text(string text, int width)` переносит текст по ширине текущего
UI-шрифта, сохраняя Unicode-символы и явные переводы строк. Ширина должна быть
положительной, иначе функция выбрасывает ошибку. Например,
`array lines = ui_wrap_text("Длинное сообщение", 240);`. Диалоги используют этот
перенос и вертикальную прокрутку, чтобы длинная ошибка оставалась доступна целиком.

### Строковые значения реестра пользователя Windows

Публичные системные функции (модуль `os`) позволяют обычным приложениям
регистрировать пользовательские интеграции без C++ расширений:

- `array registry_user_snapshot(string key, string name)` возвращает
  `[present, expandable, value]`: наличие, тип `REG_EXPAND_SZ` вместо `REG_SZ`,
  исходную строку без раскрытия `%VAR%`. Отсутствие — `[false, false, ""]`.
- `void registry_user_compare_exchange(string key, string name, array expected, array replacement)`
  сравнивает снимок, создаёт подраздел при необходимости и записывает/удаляет
  значение. Запись синхронизируется `RegFlushKey`.
- `void registry_user_remove_empty_key(string key)` удаляет только пустой
  подраздел. Отсутствие допустимо; значения или вложенные ключи вызывают ошибку.

`key` — путь относительно HKCU, начинающийся с `Software\`, с непустыми
компонентами и без завершающего разделителя. Максимум 2048 байтов UTF-8 для пути,
256 для имени, 1 МиБ для строки; NUL запрещён. Читается представление реестра
текущего процесса. Неподдерживаемый тип, конфликт снимка, ошибка доступа или ОС
дают `Registry Error`; системная ошибка содержит числовой код. Ошибка синхронизации
может означать, что новое значение уже видно. На Linux, Android и Web функции
явно недоступны. Для PATH используйте `env.user_path_plan` и `user_path_apply`.

Проверка и запись/удаление не являются атомарным CAS относительно стороннего
редактора реестра. Программа должна исключать конкурирующие изменения своих
ключей; чужие значения нельзя удалять как часть очистки.

```skrumi
using os;
string key = "Software\\MySkrumiApp";
array before = registry_user_snapshot(key, "DisplayName");
registry_user_compare_exchange(key, "DisplayName", before, [true, false, "Моё приложение"]);
// Восстановление только при неизменном установленном значении:
registry_user_compare_exchange(key, "DisplayName", [true, false, "Моё приложение"], before);
```

Подписи диалоговых кнопок задаются строками `UI_DIALOG_YES`, `UI_DIALOG_NO`,
`UI_DIALOG_CANCEL`, `UI_DIALOG_OK`. Например, `UI_DIALOG_CANCEL = "Cancel";`.
Возвращаемые идентификаторы `yes/no/cancel/ok` от локализации не меняются.

### Размеры интерфейса и рабочая область

`array desktop_metrics()` (`gfx_desktop_metrics()`) требует открытого окна и
возвращает `[width, height, preferred_scale]`. Ширина/высота — доступная рабочая
область с запасом под рамку (32/64 пикселя), минимум 64. Windows использует
логические координаты DPI virtualization и масштаб 1; повторно умножать их на
физический DPI не нужно. X11 использует геометрию root, первую EWMH work area
и `Xft.dpi` из RESOURCE_MANAGER (120–384 DPI дают масштаб до 3; иначе 1).
Это начальный ориентир для размера окна, а не отслеживание монитора при переносе.
Ошибка запроса или отсутствие окна — Graphics Error; Android и браузер возвращают
явную ошибку недоступности. Для текущей области рисования используйте
`window_width()`/`window_height()` после `window_poll()`.

- `string ui_text_field_box(string id, int x, int y, int width, int height, string text, string placeholder)`:
  поле с явной высотой, оба размера не менее 8; возвращает отредактированный текст.
- `bool ui_checkbox_box(string id, int x, int y, int side, string label, bool checked)`:
  флажок со стороной не менее 8; возвращает состояние после клика по нему/подписи.

Недопустимый размер вызывает перехватываемую ошибку. Шрифты и цвета берутся из
общей темы UI. Старые `ui_text_field` и `ui_checkbox` сохраняют размеры 28 и 14.
Диалоги автоматически увеличивают размеры и кнопки при выборе крупного `UI_FONT`.
В Builder высота поля/флажка доступна в свойствах; старые проекты без `customSize`
сохраняют прежние размеры, изменение высоты включает новое свойство.

```skrumi
using ui;
open_window(640, 480, "Размеры UI");
string name = "";
bool enabled = true;
while (window_poll()) {
    clear_window(UI_PANEL);
    name = ui_text_field_box("name", 24, 30, 300, 40, name, "Имя");
    enabled = ui_checkbox_box("enabled", 24, 90, 24, "Включить", enabled);
    present_window();
}
```
