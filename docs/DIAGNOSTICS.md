# Диагностики и отличия от C, Python и JavaScript

Сначала используйте `skrumi check file.skm` или `skrumi check --project`.
После синтаксической ошибки семантические сообщения подавляются, чтобы отсутствие
разобранного объявления не превращалось в десятки Undefined function/variable.
Парсер восстанавливает пропущенную точку с запятой перед границей блока и
некоторыми началами инструкций. Это восстановление для диагностики, не изменение
исполняемой программы: файл с ошибкой по-прежнему нужно исправить.

| Код/сообщение | Что делать |
|---|---|
| SKR1000, Invalid ... literal | Проверить цифры основания, exponent и разделители: 0xFF, 0b1010, 1_000, 1.5e3 |
| SKR1000, unterminated block comment | Закрыть комментарий `*/`; вложенные комментарии не поддерживаются |
| SKR1001, expected ';' before ... | Добавить `;` в конце предыдущей инструкции |
| SKR2001, shadows a built-in name | Переименовать объявление; LSP предлагает quick fix с изменением ссылок |
| requires int operands | Битовые операции требуют int; преобразование float делайте явно |
| shift count must be in 0..31 | Проверить число разрядов сдвига |
| prefix ++/-- is not supported | Использовать постфиксную форму или += 1 / -= 1 |
| conditional branches have incompatible types | Выбрать общий тип ветвей `?:` |
| not a function | Проверить, не затенено ли имя параметром/переменной |
| Function ... expects ... arguments | Проверить собственное объявление и alias модуля |
| Build Error: output already exists | Использовать build --force для замены executable |
| scalable outline font required | Нужен контурный TTF/OTF; bitmap-only emoji font не поддерживается |

Коды SKR1000/SKR1001 передаются CLI check и LSP. У не всех прежних runtime-
диагностик есть коды. CLI ограничивает вывод через --max-errors; LSP показывает
до 10 диагностик файла. Предупреждения не меняют exit code без --deny-warnings.
Список отключаемых кодов линтера в манифесте пока не поддерживается.

## Что отличается

| Тема | Skrumi |
|---|---|
| bool | Условия if/while/?: требуют bool; нет truthiness чисел/строк |
| Числа | int знаковый 32-битный; float→int только явно через to_int |
| Литералы | 0x/0b, разделители между цифрами, научная запись поддерживаются |
| Битовые сдвиги | 32 бита, >> со знаковым расширением, сдвиг 0..31 |
| ?? и ?: | ?: выше ??, ниже логического ||; обе конструкции ленивые |
| Структуры/массивы/map | Присваивание разделяет данные; copy — глубокая копия |
| const | Защищает привязку имени, а не вложенные данные |
| Строки | size/byte_size — байты, str_length/char_length — кодовые точки, grapheme_length — графемы |
| switch | Fallthrough сохраняется; ставьте break явно |
| ++/-- | Только постфиксные, включая поля/элементы; результат — прежнее значение |
| Функции | Нет перегрузок, default/named arguments; объявление затеняет builtin по имени |
| Модули | `using graphics as gfx;` позволяет явно выбрать экспорт |

<!-- skrumi-run -->
```cpp
struct Enemy { int hp = 3; }
array<Enemy> enemies = [Enemy()];
Enemy shared = enemies[0];
shared.hp--;
assert_equal(enemies[0].hp, 2);
Enemy independent = copy(shared);
independent.hp = 10;
assert_equal(shared.hp, 2);
const array levels = [1];
push(levels, 2); // const защищает имя, не содержимое
assert_equal(size(levels), 2);
```

Безопасное чтение уже существует: `get_or(items,index,default)` и
`get_or(map,key,default)`. Безопасный вызов `obj?.method()` тоже поддерживается.
Для долгих таймеров есть `clock_ms64()` (float миллисекунды); исходный clock_ms
остаётся int и имеет предел около 24.8 суток. Новый отдельный целочисленный int64
не вводится этим API.

## Пока отсутствует

`??=`, safe-index синтаксис, автоматическое сужение nullable, is/as,
readonly/frozen, do/while, метки break/continue, switch-выражения, перегрузки и
параметры по умолчанию не реализованы. Используйте обычные if/while, get_or,
отдельные функции и глубокие копии. Эти ограничения не следует путать с уже
добавленными тернарными/битовыми операциями, литералами и блочными комментариями.
