# Проекты, проверка и сборка

```sh
skrumi init my-game
cd my-game
skrumi run .
skrumi check --project
skrumi test
skrumi build .
skrumi build . --force
```

`init` создаёт `main.skm`, `skrumi.toml`, `.gitignore`, `tests/smoke_test.skm`.
Если любой из этих файлов существует, команда отказывается до записи файлов.
Обычный запуск `skrumi main.skm` продолжает работать.

```toml
name = "moon-forest"
version = "0.1.0"
entry = "main.skm"
resources = "assets"

[lint]
deny_warnings = false
```

Манифест разбирается полноценным TOML-парсером. `name` — ASCII-буквы, цифры,
дефис или подчёркивание; это имя выходного файла. `entry` — относительный `.skm`,
`resources` — необязательный относительный каталог. `..` и абсолютные пути
отклоняются. Неизвестные ключи — ошибка, чтобы опечатки не игнорировались.
Пока манифест не является менеджером зависимостей: `using` и `include` работают
по существующим правилам. Поля dependencies/formatter пока не поддерживаются.

`build .` читает манифест и пишет `build/<name>` (в Windows — `.exe`).
`-o` и `--resources` переопределяют путь результата и ресурсов. `--force`
собирает и валидирует новый executable во временном каталоге на том же томе,
затем атомарно заменяет прежний файл. Ошибка упаковки сохраняет старый executable.
Ссылки, каталоги, исходники `.skm` и совпадение input/output не перезаписываются.
Без `--force` прежний отказ при существующей цели сохраняется.

`check directory` проверяет все `.skm` рекурсивно, исключая скрытые каталоги,
каталоги с префиксом build и node_modules. `check --project` дополнительно
читает `skrumi.toml` текущего каталога и его `lint.deny_warnings`.
`--deny-warnings` делает предупреждения ошибкой CI, но по умолчанию они не меняют
код возврата. `--max-errors N` ограничивает вывод диагностик каждого файла
(по умолчанию 10, 1..10000). После синтаксической ошибки CLI подавляет последующие
семантические сообщения этого файла; сначала исправляется синтаксис.

`test` автоматически ищет `*_test.skm`; явный путь вроде
`skrumi test tests/smoke.skm` допускается. Если в явно указанном файле нет
`test_...` функций, выполняются его верхнеуровневые проверки. Файл с test-функциями
сохраняет изоляцию: каждый тест запускается в новом интерпретаторе.
Используйте `random_seed` внутри теста для воспроизводимого сценария.

## Миграция

- Добавлены `?:`, битовые операции, новые литералы, блочные комментарии, BOM,
  постфиксные изменения полей/элементов. Префиксные ++/-- отсутствуют.
- Приоритет `< <= > >=` теперь выше `== !=`, как в C. Если старый код полагался
  на общий уровень сравнения, явно расставьте скобки.
- `??`, ссылки структур, поверхностный const и switch fallthrough сохранены.
- `size(string)` по-прежнему возвращает байты; новые явные имена устраняют неоднозначность.
- `SKR2001` предупреждает о затенении встроенных имён в месте объявления.
  `using graphics as gfx;` позволяет явно вызвать `gfx.draw_frame(...)`.
- `clock_ms()` сохраняет тип int; для долгих процессов используйте `clock_ms64()`.
- Данные шрифтов, Unicode и микшера закреплены хешами при сборке.

Список новых API: [справочник](../DOCUMENTATION.md#игровые-и-проектные-api).
